## 一、设计决策记录

### 1. 视觉风格：雾态地平线（沿用 Demo 原始设计）
- **选定方案**：直接采用用户提供的 Demo（`现象学100讲 · 网页Demo.html`）中的"雾态地平线"配色体系
- **理由**：Demo 的冷色调雾态基调、地平线光晕（`--horizon-glow: #e8b26a`）与现象学"悬置—回到事物本身—走向生活世界"的哲学意象高度契合；六模块从冷到暖的色谱（胡塞尔的冷灰蓝 → 跨学科整合的暖金）暗合课程从"方法奠基"到"多元敞开"的整体运动轨迹
- **未做改动**：未引入 Demo 之外的新配色，严格保留原始 CSS 变量命名与数值

### 2. 站点架构：采用"唯识学100讲"的成熟工程模式，而非重新设计
- **决策**：参考已上线的姊妹项目 `Vijñaptimātratā/`（唯识学100讲）的目录结构——`index.html`（导航总览）+ `assets/style.css` + `assets/script.js`（公共样式与脚本）+ `lessons/lesson-XXX.html`（单讲页面）
- **理由**：唯识学100讲已经过实战验证（100讲全部上线，含筛选、进度条、已读标记、雾态/晴朗主题切换、字号调节、移动端 TOC 抽屉等完整交互），复用其工程模式可以保证现象学站点从第一天起就具备同等的可用性与可维护性，避免重新发明轮子
- **改动**：将唯识学站点的"暗色模式"命名为"雾态模式"（`data-theme="fog"`），与现象学 Demo 原始的雾态美学命名保持一致；四角色配色（溯源者/描述者/诤者/还归者）替换为 Demo 原始设定的配色而非唯识学的四色

### 3. 内容生成工程：JSON数据 + Python模板渲染，而非手写HTML
- **决策**：每讲内容先写入独立的 `lessons/content/lesson-XXX.json`（结构化的角色数据），再通过 `generate_lesson.py` 统一渲染为最终HTML
- **理由**：100讲的体量决定了必须用工程化方式保证输出格式的一致性（面包屑、角色区块顺序、法义卡片、上一讲/下一讲导航等），手写HTML极易在repetitive structure中引入不一致或遗漏
- **技术细节**：由于中文正文大量使用双引号（"..."），直接写JSON文件极易因引号冲突产生解析错误。改为使用 Python 脚本（`lesson_data_XXX.py`）以Python字符串形式书写正文（可自由使用ASCII直引号），再通过 `lesson_json_helper.py` 的 `smart_quotes()` 函数自动将正文中的英文直引号转换为中文弯引号（"..."→\u201c...\u201d），最终输出合法JSON。这一"Python写作层 + 自动转换 + JSON存储 + 模板渲染"的四层流水线，是本项目相较于唯识学100讲手写HTML方式的一处工程改进

### 4. 四类特殊讲次的差异化排版模板
- **常规讲**：溯源者（Ursprung）→ 描述者（Deskription）→ 诤者（Widerstreit）→ 还归者（Rückkehr），四个色块依次纵向排列，比例约25%/35%/25%/15%（通过段落数量体现，非严格字数配比）
- **碰撞讲（⚡）**：改为"现象学理论"面板 + "学科B理论"面板左右并排（`collision-grid`，移动端自动折叠为上下），中间以VS分隔线过渡，底部单独一个虚线框的"核心悖论"区块，视觉上强调"对撞感"
- **辩证讲（⚖）**：立场A → 立场B → 未解的分歧点，三个纵向色块，其中"未解的分歧点"使用诤者色系的虚线边框，强调"故意不给结论"的开放性
- **元洞见讲（🔗）/模块收尾讲（◆）**：复用常规讲的四角色结构模板（因为课程Prompt要求元洞见"回顾但不总结"、模块收尾"呈现未完成的张力"，这两种精神与"诤者"环节的功能高度重合），但在页面顶部增加一个金色胶囊状的"本讲回顾范围"标签（仅元洞见讲），提示读者这一讲的特殊性质

### 5. 导航总览页：模块可折叠 + 双重筛选（模块 × 讲次类型）
- **决策**：100张课程卡片按六大模块分组展示，每个模块标题栏可点击折叠/展开；筛选栏支持按模块（M1-M6）与按类型（⚡/⚖/🔗/常规）两个维度独立筛选，两者可叠加使用
- **理由**：100讲的信息密度远超唯识学站点单模块10-25讲的规模上限（现象学模块四多达16讲），可折叠设计避免首屏信息过载；双重筛选让读者能快速定位"我只想看所有碰撞讲"或"我只想看模块三的内容"这类具体需求

### 6. 面包屑与返回路径的三层结构
- **根目录**（`ego1013.github.io/ethanycjin/`）→ **课程导航页**（`phenomenology/index.html`）→ **具体讲次页**（`phenomenology/lessons/lesson-XXX.html`）
- 每个讲次页顶部同时提供：① topbar左上角"← Ethan's Lab"（回根目录）+ "现象学100讲"（回导航页）的二级面包屑；② 正文顶部的三级面包屑"首页 > 模块名 > 第N讲"；③ 底部"上一讲 / 返回目录 / 下一讲"三向导航。三层冗余设计确保读者在深度阅读单篇课程时，永远不会迷失在站点结构中

## 二、内容创作决策（第1-10讲）

### 1. 术语精确性优先于流畅性
- 所有德语/法语原文术语（Epoché、Wesensschau、noesis/noema、Lebenswelt等）均在首次出现时标注原文，且在溯源者环节给出具体的文献出处（章节号），严格遵循Prompt"精确定义术语原初含义"的要求
- 放弃了"先用中文讲清楚、术语作为补充"的更易读写法，改为"中文表述与德文术语同步出现"，因为受众（Ethan）已具备哲学背景，术语精确性比入门友好度更重要

### 2. 描述者环节的场景选择：日常化而非文学化
- 第1讲选择"看一只杯子"、第2讲选择"喝汤""听到熟悉的声音"、第4讲选择"看一张椅子""地震时的房间"——均选择极度日常、任何读者都能立即在自己生活中验证的场景，而非诗意化或文学化的场景
- 理由：严格执行Prompt"必须包含至少一个具体到可被读者自己验证的生活场景"的要求，日常场景的可验证性远高于文学化场景

### 3. 诤者环节的分歧呈现：不预设胜负，但给出双方最强论证
- 第2讲呈现布伦塔诺与胡塞尔关于意向性"心理学 vs. 超越论"的分歧、第8讲呈现noema诠释的"西岸 vs. 东岸"论战——均只呈现双方论证的实质内容，不在文中给出"哪一方更正确"的编辑判断
- 第9讲（碰撞讲）严格执行"你以为在说X，其实它在暗示更颠覆的Y"的悬置式收尾，未强行调和现象学与认知科学表征理论

### 4. 还归者环节的练习设计：限时、可操作、避免说教语气
- 所有练习严格控制在90秒至4分钟之间，分步骤给出精确的秒数分配（如"第一步（30秒）"），确保读者可以直接按照文本操作，而非阅读一段抽象的冥想指导
- 语言上使用"你会发现""留意一下"等邀请式表述，避免"你应该""你必须"等指令式语气

### 5. 元洞见/模块收尾讲的特殊处理（第10讲）
- 第10讲作为模块阶段收尾（不是完整模块收尾，因为模块一延伸至第20讲），明确在"诤者"环节列出三组尚未解决的张力，并在"还归者"环节设计了一个"向内/向外姿态切换"的身体性练习，为读者切换进入模块二做准备，而非简单复述前9讲内容

## 三、修改建议（后续迭代）

### 高优先级
1. **课程进度持久化**：当前使用 localStorage，仅在同一浏览器/设备上有效，无跨设备同步；未来可考虑接入轻量后端或云同步方案
2. **术语索引页**：随着课程推进到20、30讲后，术语量会迅速膨胀（Epoché、Dasein、noema、Lebenswelt……），建议增加一个独立的"术语索引"页面，按字母/拼音排序，点击可跳转到该术语首次详细讲解的具体讲次
3. **原文引文的双语对照优化**：目前德/法文原文以斜体标注在正文中，随文本量增加，建议引入可折叠的"原文对照"浮层，避免打断中文阅读节奏

### 中优先级
4. **模块间关联图谱**：文字化的"connection"字段已经记录了讲次间的前后连接，但100讲全部完成后，建议生成一张可视化的"概念关联网络图"，让读者直观看到比如"意向性"这一概念如何在第2、8、9、13、14、49、88讲反复被调用与深化
5. **移动端阅读体验优化**：碰撞讲的左右并排面板在移动端会折叠为上下堆叠，需要在讲次数量增多后重新审视这一移动端交互是否足够清晰
6. **搜索功能**：100讲全部上线后，建议增加全文搜索，方便读者快速定位到讨论某个具体概念或哲学家的所有讲次

### 低优先级
7. **音频版本**：还归者环节的悬置练习，未来可考虑配合简短的引导音频，增强"停下来做练习"的实际执行率
8. **打印/导出优化**：`assets/style.css` 已包含基础的 `@media print` 样式，未来可针对法义卡片与引文块做更精细的打印排版优化

## 四、技术栈决策

| 维度 | 决策 | 理由 |
|------|------|------|
| 框架 | 纯 HTML/CSS/JS，无框架 | 静态部署 GitHub Pages，无构建步骤，与站内其他项目保持一致 |
| 字体 | Noto Serif SC + Noto Sans SC + JetBrains Mono | 中文衬线体（正文）+ 无衬线体（UI元素）+ 等宽字体（术语编号、原文标注），三字体分工明确 |
| 部署 | GitHub Pages（`ego1013.github.io/ethanycjin/phenomenology/`） | 与唯识学100讲、佛学100讲等姊妹项目保持一致的部署路径规范 |
| 内容生产 | JSON数据 + Python模板渲染（`generate_lesson.py`） | 保证100讲输出格式的一致性，同时通过`lesson_json_helper.py`解决中文引号与JSON转义的冲突问题 |
| 动画 | CSS transition，无JS动画库 | 轻量级，不依赖第三方库，与站内其他项目技术栈保持一致 |
| 响应式 | 900px / 640px 双断点 | 桌面端（含侧边栏TOC）/ 平板端（侧边栏隐藏，TOC抽屉）/ 手机端（单列卡片网格） |

## 五、文件结构

```
phenomenology/
├── index.html                    ← 100讲导航总览页
├── generate_index.py              ← 导航页生成脚本（含完整100讲目录数据）
├── generate_lesson.py             ← 单讲页面生成脚本（模板渲染引擎）
├── lesson_json_helper.py          ← JSON转义辅助工具（智能引号转换）
├── lesson_data_00N.py             ← 第N讲内容源文件（Python书写，含正文全文）
├── lessons_data.json              ← 导出的100讲目录结构化数据（供未来功能复用）
├── assets/
│   ├── style.css                  ← 全站公共样式（雾态地平线设计系统）
│   └── script.js                  ← 全站公共脚本（筛选/进度条/主题/TOC/已读标记）
└── lessons/
    ├── content/
    │   └── lesson-00N.json        ← 第N讲结构化内容数据（由 lesson_data_00N.py 生成）
    └── lesson-00N.html             ← 第N讲最终页面（由 generate_lesson.py 渲染）
```

**当前完成状态**：第1-10讲（模块一·方法的诞生 全部完成）已生成正式内容并上线；第11-100讲的目录结构、卡片、类型标记已在导航页中完整呈现，但正文内容尚待后续批次生成（对应课程Prompt要求的"分批交付，每批建议5讲"）。
