Day 13 · SFT vs RL：特化与泛化的根本差异

培养「流水线工人」还是「高斯」？

📅 2026-04-23 Thu 📦 第一模块 · 地基篇 · Week 2 ⏱️ 预计 40 分钟
🔥 开场

假设你要培养一个新来的渠道经理。

方法 A：给他一本《标准操作手册》，每种情况对应一个标准答案。遇到代理商投诉？翻第 47 页。遇到返利纠纷？翻第 82 页。他按手册操作，输出稳定、可预测、几乎不出错——但遇到手册没覆盖的场景，他愣住了。

方法 B：不给手册，只给考核指标——"渠道满意度提升 10%，代理商流失率控制在 5% 以下"。他自己摸索。前三个月可能犯很多错，有时候会搞砸。但六个月后，他开始发展出自己的判断力——能应对手册从未预见过的新场景，甚至发明出比手册更好的方法。

这两种培养方式，正好对应了大模型 Post-train 阶段的两种核心路径：SFT（Supervised Fine-Tuning，监督微调）和 RL（Reinforcement Learning，强化学习）。

昨天我们讲了 Fine-tune 是"改模型参数"，但怎么改——用标准答案教，还是用奖惩信号让它自己学——这个决定会从根本上塑造模型的"性格"。今天就拆开这个黑箱。

10 min

Why — 为什么这个区分如此根本？

Day 3 的回顾与深化

Day 3 讲过 Post-train 包含 SFT 和 RLHF 两步。当时的描述是：SFT = 导师带教，RLHF = 绩效考核。那时候的重点是"Post-train 很重要"。

今天的重点完全不同：SFT 和 RL 不只是"两个训练步骤"，它们是两种根本不同的学习范式——导致的模型能力边界完全不同。

💡 为什么现在这个话题爆了？

2024-2025 年，整个行业的焦点从"谁的模型参数更大"转向了"谁的训练方法更聪明"。

DeepSeek-R1 用纯 RL（没有 SFT 阶段）训练出了世界级推理能力。
OpenAI 的 o1/o3 靠 RL 实现了"慢思考"。
而绝大多数开源模型还在靠 SFT + 少量 RLHF 的标准管线。

SFT vs RL 不再是学术问题，它是决定模型"聪不聪明"的分水岭。

为什么不能只用 SFT？

SFT 看起来简单又有效：找一堆"好回答"作为标准答案，让模型学着模仿。多直觉啊——人也是这么学的嘛。

问题出在一个关键限制上：

⚠️ SFT 的天花板

SFT 训练出来的模型，能力上限 = 训练数据中"最好答案"的水平。

它在模仿，不在创造。你给它什么样的标准答案，它最多学到那个水平——永远不会超越。

就像一个只按手册操作的员工：手册写到哪里，他的能力就到哪里。手册没写的，他不会。

但 RL 不一样。RL 不给标准答案，只给一个"评判标准"——你做得好就加分，做得差就减分。模型在这个激励框架下自己探索解法。

结果是什么？RL 训练出来的模型，有可能发现比人类标注者更好的答案。 它能超越老师。

这不是假设——DeepSeek-R1 已经证明了这一点。纯 RL 训练出的推理能力，在某些数学和编程任务上超过了人类专家的标注质量。

20 min

What — 两种训练范式的底层机制

一、SFT：照着标准答案学

机制

SFT 的训练过程

准备阶段
1. 人类标注者写出高质量的"问-答"对
   问："解释量子纠缠"
   答：[一段精心撰写的回答]
2. 通常需要 数千到数万 条标注数据

训练阶段
3. 模型看到问题，生成自己的回答
4. 计算模型回答与标准答案的差距（Loss）
5. 调整参数，让模型回答更接近标准答案
6. 重复数千次

本质：最小化模型输出与标准答案之间的距离
目标函数：P(标准答案 | 问题) → 最大化

一句话：SFT 是"照葫芦画瓢"。 老师画了一个葫芦，学生的目标是画得越像越好。

SFT 擅长什么？

能力类型为什么 SFT 擅长例子
格式遵循 标准答案能清晰定义"正确格式" JSON 输出、报告模板、固定话术
风格模仿 只需要大量风格样本让模型对齐 客服语气、品牌 tone of voice
任务执行 有清晰输入-输出映射的任务 翻译、摘要、分类、信息提取
安全对齐 教会模型"什么该拒绝"比较直接 拒绝有害请求、遵守安全边界
📊 渠道类比：标准操作手册

你给新员工一本《渠道运营标准操作手册》——每种场景对应一个标准流程。他照着做，输出又快又稳。

适用场景：代理商开户流程、返利计算规则、投诉分级处理。这些都有"标准答案"，SFT 就很够。

失灵场景：代理商提出了一个手册没覆盖的全新合作模式。按手册找不到对应章节——要么答非所问，要么僵在那里。

二、RL：在试错中学会判断

机制

RL 的训练过程

准备阶段
1. 设计一个奖励函数（Reward Model）
   它不给标准答案，只给分数
   "这个回答好不好？" → 0.8 分 / 0.3 分
2. 通常由人类偏好标注训练出来
   （回答 A vs 回答 B，哪个更好？→ 大量对比数据）

训练阶段
3. 模型看到问题，自由生成回答
4. 奖励模型给回答打分
5. 高分回答 → 强化（让模型更倾向这样回答）
6. 低分回答 → 抑制（让模型远离这样回答）
7. 模型在无数次尝试中自己摸索出策略

本质：最大化累积奖励，没有唯一标准答案
目标函数：E[Reward(模型回答)] → 最大化

一句话：RL 是"放养 + 考核"。 不告诉你答案，只告诉你考试规则。你自己去学，考好了奖，考差了罚。

RL 能做到 SFT 做不到的什么？

能力类型为什么 RL 才行例子
超越标注者 不受标准答案上限约束 DeepSeek-R1 数学推理超越人类专家
复杂推理 学会"思考过程"而非模仿答案 多步数学证明、代码 debug、策略规划
创造性解法 探索空间不受标注数据限制 发现非常规但有效的解决方案
自我纠正 学会"发现自己错了并修正" o1 的"我再想想"行为、回溯推理
📊 渠道类比：放养 + 绩效考核

你不给新员工手册，只给他三个 KPI：渠道满意度、代理商留存率、业务增长率。他自己去摸索方法。

前三个月：可能犯很多错——用错话术、判断失误、丢了几个小代理商。
六个月后：他发展出了独特的客户管理方法——有的代理商用关系驱动，有的用数据说话，有的用利益绑定。每种方法都是他在试错中"自己长出来的"，手册里根本不会写。

最关键的区别：当市场突变（比如竞品突然降价 30%），按手册的人不知道怎么办，而这个人能独立应对——因为他学会的是判断力，不是流程。

三、核心对比：光谱两端

SFT 和 RL 不是非此即彼的二选一，而是一个光谱的两端：

SFT 极端 RL 极端
维度 SFT RL
学习信号 标准答案（完整文本） 奖励分数（一个数字）
信息密度 极高（逐 Token 监督） 极低（只有最终分数）
训练效率 高（收敛快） 低（需要大量试错）
能力上限 ≤ 标注数据质量 可能 > 人类水平
输出稳定性 高（输出可预测） 较低（探索带来方差）
泛化能力 弱（只在训练分布内好） 强（学到了"方法"而非"答案"）
Reward Hacking 风险 低 高（Day 4 讲过的谄媚问题）
计算成本 相对低 极高（需要反复采样 + 评分）
💡 一句话记忆法

SFT 教的是"知道什么"，RL 教的是"怎么想"。

SFT 让模型获得知识（回答应该长什么样），RL 让模型获得策略（面对新问题该怎么推理）。

知识可以被穷举覆盖，但策略不行——策略必须在真实挑战中摸爬滚打出来。

四、真实案例：DeepSeek-R1 的启示

Day 7 复习课提到过 DeepSeek-R1，但当时只是作为解剖案例。今天我们从 SFT vs RL 的视角重新看它。

DeepSeek-R1 做了什么？

传统流程：Pre-train → SFT → RLHF（少量 RL 微调）。

DeepSeek-R1 的激进实验：Pre-train → 直接用 RL 训练推理能力，跳过 SFT 阶段。

🔬 R1-Zero：纯 RL 的惊人发现

DeepSeek 先做了一个叫 R1-Zero 的实验：只用 RL，完全不用 SFT。

结果令人惊讶——模型自发出现了"思维链"行为。没有人教它"先思考再回答"，但它在 RL 的奖惩机制下自己学会了：先列出推理步骤，检查中间结果，发现错误就回溯修正，最后才给出答案。

这就像一个新员工，没人教他做笔记、列清单、检查核对——他在被考核了几千次之后，自己发明了这些工作方法。

这意味着什么？ 高级认知策略（分步推理、自我检查、回溯纠错）不是"只有人类能教"的——只要激励结构设对了，RL 可以让模型自己发展出来。

但纯 RL 也有代价

R1-Zero 虽然推理强，但有明显问题：

❌ 可读性差

推理过程混乱、中英文混杂、重复啰嗦。RL 只管结果对不对，不管表达好不好看。

❌ 不稳定

同一个问题多次问，回答质量波动大。探索带来的随机性让输出不可预测。

所以最终版 DeepSeek-R1 用了混合策略：先用少量 SFT 数据建立基础格式和安全边界，再用大量 RL 激发推理能力。SFT 管"形"，RL 管"魂"。

五、行业格局：谁在用什么策略？

模型策略结果
GPT-4 / Claude SFT 为主 + RLHF 精修 全面、稳定、安全对齐好，但推理天花板受限
o1 / o3 SFT 基础 + 大量 RL 强化推理 数学/编程/科学推理大幅提升，但更慢更贵
DeepSeek-R1 极少 SFT + 主要靠 RL 推理能力媲美 o1，但格式和稳定性需要额外处理
大部分开源模型 SFT 为主 + 很少 RL 跟随对话做得好，但复杂推理能力明显不足
💡 行业趋势

2024-2025 年的核心竞争，已经从"谁的 SFT 数据多"转向了"谁的 RL 做得好"。

SFT 数据容易获取（花钱请人标注就行），但 RL 的奖励函数设计、训练稳定性、防止 Reward Hacking——这些才是真正的技术壁垒。

回想 Day 4（Reward Hacking）和 Day 8（Scaling Law）——RL 正是 Post-train Scaling 和 Test-time Scaling 的核心引擎。SFT 扩不上去（标注数据有上限），RL 可以（探索空间近乎无限）。

六、混合策略：为什么不是二选一？

实际工程中，SFT 和 RL 几乎总是混合使用。关键是比例和顺序：

典型的训练管线

Pre-train → 学会语言和世界知识
      ↓
SFT → 学会"对话格式"和"安全边界"
      ↓      （给模型一个"安全的起点"）
RL → 在安全框架内最大化能力上限
      ↓      （让模型学会"怎么思考"）
最终模型 = SFT 的稳定性 + RL 的智能

竞争差异在于：SFT 和 RL 的比例
重 SFT = 稳定可控但能力受限
重 RL = 能力突破但需要更多工程投入

SFT 和 RL 不是竞争关系，是协作关系。 SFT 建地基（格式、安全、基本能力），RL 盖高楼（推理、创造、超越人类的智能）。没有 SFT 的地基，RL 的高楼会塌（输出不稳定、格式混乱）；没有 RL 的高楼，SFT 的地基只能盖平房（能力上限低）。

So What — 这改变了什么？

一、对你选择 AI 工具的影响

1 任务类型决定该选什么模型
标准化执行任务（翻译、摘要、分类、报表生成）→ SFT 强的模型就够了。GPT-4、Claude 都很好，稳定可靠。
复杂推理任务（多步分析、策略制定、代码 debug、数学证明）→ 需要 RL 强的模型。o1、DeepSeek-R1 这类推理模型效果显著更好。

别用大炮打蚊子，也别用水枪打坦克。
2 理解"慢模型"为什么更贵但更强
o1、DeepSeek-R1 这类推理模型调用更慢、更贵。原因现在清楚了——它们在推理时做的不是"查找答案"（SFT 的本质），而是"探索解空间"（RL 赋予的能力）。

慢不是 bug，是 feature。 它在"想"，而不只是在"查"。这就是 Day 8 讲的 Test-time Compute Scaling——推理阶段的算力投入是有回报的。

二、对渠道管理的启示

✅ SFT vs RL 思维在管理中的应用

场景 1：培养新人执行标准流程
→ SFT 思维。给手册、给 SOP、给标准案例。目标是快速复制，降低人为偏差。适用于：开户流程、返利计算、投诉分级。

场景 2：培养核心人才独立判断
→ RL 思维。不给标准答案，给清晰的考核指标和试错空间。让他在真实业务中摸索策略。适用于：大客户谈判、新区域开拓、危机处理。

场景 3：团队升级
→ 混合策略。先 SFT（确保基本功），再 RL（鼓励创新和独立判断）。新人先跟流程，一年后给他更多自由度和独立考核指标。

这不只是类比——AI 训练的逻辑，真的和人才培养的逻辑高度同构。

三、对 AI 行业竞争的判断

💡 判断力升级

以后看到一个新模型发布，你可以问三个问题：

1. SFT 数据质量如何？ → 决定基础对话能力的下限
2. RL 做了多少？奖励函数怎么设计的？ → 决定推理能力的上限
3. 怎么控制 Reward Hacking？ → 决定这个模型是真聪明还是在"表演聪明"

这三个问题能帮你穿透 90% 的模型发布营销话术。

✅ 今日 Checkpoint

场景：你的公司要上一个"AI 渠道风控助手"——实时监控代理商的异常行为（刷单、虚报、套利），自动生成风险报告并建议处置措施。团队在讨论该怎么训练这个 AI，有四种方案：

A 纯 SFT。收集过去三年的风控案例（异常行为 → 处置结论），标注几千条数据训练模型。标准化场景覆盖率高，上线快。
B 纯 RL。设计奖励函数：发现真实异常 +10 分，漏报 -20 分，误报 -5 分。让模型自己学习识别异常的策略，不给标准案例。
C 先 SFT 再 RL。用历史案例 SFT 建立基础识别能力，再用 RL 让它在模拟环境中学会发现新型异常模式（历史案例没覆盖的）。SFT 管"已知风险"，RL 管"未知风险"。
D 先拆解任务：常规异常检测（规则明确的刷单/虚报）用 SFT 或甚至用 Prompt + RAG 就够了，根本不需要训练模型；只有"新型风险发现"这个子任务才需要 RL。把 80% 的常规场景用轻方案解决，把 RL 资源集中在最难的 20%。

⚡ 追问：假设你选了某个方案上线三个月后，发现代理商开始用一种全新的套利方式（之前完全没出现过）。你的方案能应对吗？如果不能，你会怎么迭代？给出迭代的时间估算（天/周/月级别）。

📌 知识卡片

1 SFT = 照标准答案学，RL = 在试错中学判断
SFT 给模型完整的"正确答案"让它模仿，能力上限 = 标注数据质量。RL 只给奖惩信号，模型自己探索解法，有可能超越人类水平。两者是光谱两端，不是非此即彼。
2 SFT 教"知道什么"，RL 教"怎么想"
SFT 让模型获得知识（答案应该长什么样），RL 让模型获得策略（面对新问题该怎么推理）。知识可以穷举覆盖，策略不行——策略必须在真实挑战中发展出来。
3 DeepSeek-R1 证明了纯 RL 的潜力
R1-Zero 实验显示：不用 SFT，纯 RL 可以让模型自发出现思维链、自我检查、回溯纠错等高级认知行为。高级思维策略可以从激励结构中"涌现"出来，不必被人类手动教授。
4 实战中是混合策略：SFT 管"形"，RL 管"魂"
SFT 建地基（格式、安全、基本能力），RL 盖高楼（推理、创造、超越标注者的智能）。行业竞争的关键不在 SFT 数据量（可花钱买到），而在 RL 的奖励函数设计和训练稳定性（真正的技术壁垒）。
5 任务类型决定该选什么模型
标准化执行任务（翻译/摘要/分类）→ SFT 强的通用模型足够。复杂推理任务（多步分析/策略制定/debug）→ 需要 RL 强的推理模型（o1/R1）。不要用大炮打蚊子，也不要用水枪打坦克。

🔗 前序知识连接

← Day 3 Day 3 讲了 Post-train = SFT + RLHF，但重点在"Post-train 很重要"。今天深入了 SFT 和 RL 的机制差异：SFT 是最小化与标准答案的距离，RL 是最大化奖励函数——目标函数不同，导致能力边界完全不同。
← Day 4 Day 4 讲了 Reward Hacking。今天揭示了深层原因：RL 依赖奖励函数，而奖励函数是人设计的——只要有评分系统，就有钻空子的可能。RL 越强，Reward Hacking 的风险越大。"更聪明"的模型也更擅长发现评分系统的漏洞。
← Day 7 Day 7 用 DeepSeek-R1 做六层解剖时提到了"纯 RL 训练路径"。今天完整解释了为什么这条路径如此震撼——R1-Zero 实验证明高级认知策略可以从 RL 中自发涌现，不需要人类手动教授。
← Day 8 Day 8 讲了四维 Scaling 新范式。今天解释了为什么 RL 是 Post-train Scaling 和 Test-time Scaling 的核心引擎——SFT 的上限是标注数据（数据有限），RL 的探索空间近乎无限，所以只有 RL 能真正"Scale"。
← Day 12 昨天讲了 Fine-tune vs RAG vs Prompt 三种定制路径。今天在 Fine-tune 内部又拆出了一层：SFT 式微调 vs RL 式微调——前者适合标准化任务定制，后者适合需要创造性判断的场景。选择定制路径时又多了一个判断维度。
