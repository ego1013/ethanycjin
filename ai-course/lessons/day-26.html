DeepSeek：开源路线的破局点

当一家量化基金把"公开考试答案"变成了瓦解闭源定价的武器

📅 2026-05-13 Wed ⏱️ 40 分钟 🟡 半衰期：中
🔥 开场问题

2025 年 1 月 20 日，美国各大科技公司的股价在一天之内蒸发了超过 1 万亿美元。英伟达单日跌幅 17%——史上最大单日市值损失。

不是因为战争、不是因为金融危机。

而是因为一家中国量化基金旗下的 AI 实验室——DeepSeek——发布了一个开源模型。

一个模型的发布，怎么能撬动万亿美元的市场震荡？它到底击中了 AI 行业的哪根神经？

10 min

Why — 为什么 DeepSeek 是一个转折性事件？

不只是"又一个开源模型"

在 DeepSeek 之前，开源模型的叙事一直是："开源追赶闭源，但始终落后一代"。Meta 的 LLaMA 系列虽然推动了开源生态，但与 GPT-4/Claude 之间始终存在明显的能力差距。

DeepSeek-R1 的发布改变了这个叙事——不是"追平"，而是在特定维度上证明了一条完全不同的路径：

  • 推理能力：数学/代码基准测试上接近 o1 水平（AIME 2024 数学竞赛通过率 79.8% vs o1 的 79.2%）
  • 训练成本：公开声称 ~557 万美元 vs OpenAI 的 o1 估算 ~5000 万美元以上——约 1/10
  • 关键决定：完全开源——模型权重公开，任何人可以免费下载部署
为什么华尔街恐慌

华尔街恐慌不是因为 DeepSeek 本身——而是因为它瓦解了一个关键假设：

"顶级 AI 能力 = 海量算力投入 = NVIDIA GPU 无限购买 = 科技巨头持续高资本支出"

如果 DeepSeek 证明了"用 1/10 的算力可以达到同等推理水平"——那整个产业链的估值逻辑就需要重估：

  • NVIDIA 的 GPU 需求会不会远低于预期？（→ 股价暴跌）
  • 闭源模型的定价权还能维持多久？（→ OpenAI 估值承压）
  • 云计算厂商的 AI 基建投资回报率会不会大幅下降？（→ 微软/Google/Amazon 承压）

一个模型 → 撬动一个产业链的估值基础。这就是 DeepSeek 的冲击波。

对你的直接价值

三个层面：

  1. 成本判断力——Day 22-25 我们评估了四家供应商的能力边界。DeepSeek 加入后，"能力"不再是唯一维度——"同等能力的成本"变成了核心判断变量
  2. 开源 vs 闭源的战略判断——Day 7 复习课你第一次遇到开源 vs 闭源的选择题（Checkpoint 选了 D——先看任务需求）。今天给你做选择的完整武器
  3. 技术路线的底层逻辑——Day 13 讲的 SFT vs RL，在 DeepSeek 身上有了最极致的实验验证——纯 RL 训练的 R1-Zero 自发涌现了思维链，这是整个课程的一个关键回环

What — DeepSeek 的路径解剖

一、谁是 DeepSeek？

DeepSeek 的背景在五家中最特殊：

维度DeepSeek对比
母公司幻方量化（High-Flyer Quant）——中国头部量化基金其他四家都是纯 AI 公司或科技巨头
创始人梁文锋——幻方量化联合创始人，长期 AI 研发投入不是学术界出身，而是金融+技术交叉背景
资金来源母公司自有资金（幻方量化管理规模百亿级）——不需要外部融资OpenAI 依赖微软 / Anthropic 依赖 Google&Amazon / Kimi 依赖 VC
算力储备2023 年已囤积 ~10,000 张 A100（芯片禁令前采购）不如巨头但有自主可控的算力底座

这个背景为什么重要

DeepSeek 的独特之处：它不需要靠卖模型赚钱。

OpenAI 需要通过 API 收入证明估值。Anthropic 需要通过企业合同维持烧钱节奏。Kimi 需要融资来续命。

但 DeepSeek 的"客户"是它自己的量化交易系统——AI 是成本中心而非利润中心。这意味着：

  • 它有最强的动力做"成本效率"——因为省下的算力直接转化为量化交易的利润
  • 它可以无顾忌地开源——因为"让别人也用"不会损害它的核心业务
  • 它没有商业化压力驱动的短期妥协——可以做更长期的技术探索

渠道管理类比：想象一个代理商的老板同时开着一家利润丰厚的其他生意。这个代理商可以"不赚钱"也活得很好——它可以用低价甚至免费来搅动市场，因为竞争本身不是目的，打磨能力才是目的。对于那些"靠利润续命"的竞争对手来说，这种选手最可怕。

二、DeepSeek 的技术路径——三大创新

创新 1：纯 RL 训练出推理能力（R1-Zero 实验）

Day 13 我们讲了 SFT vs RL 的根本差异。当时的结论是"SFT 管'形'，RL 管'魂'"——但行业共识是两者必须配合使用。

DeepSeek 做了一个激进实验：R1-Zero——完全跳过 SFT，直接用纯 RL 训练推理能力。

R1-Zero 的实验设计

输入：一个只经过 Pre-train 的基座模型（DeepSeek-V3-Base），没有经过 SFT 对齐

训练方式：纯 RL（GRPO 算法），奖励信号只有两种——"答案对了"和"答案错了"

不给什么：不给 CoT 示范、不给格式模板、不给人类推理过程作为参考

观察到什么：模型自发涌现了以下行为——

  • ✅ 自发产生思维链（"let me think step by step"类似的推理过程）
  • ✅ 自发尝试多种解法并做自我验证
  • ✅ 自发学会了回溯和纠错（"wait, that's not right, let me reconsider"）
  • ✅ 出现了"Aha moment"——推理过程中突然发现前一步的错误并重新推导

这个实验的意义极其深远——回到 Day 13 的语言：

Day 13 的核心论断被验证

Day 13 我们说"RL 独有的能力是超越标注者"——SFT 的天花板是人类标注者的水平，但 RL 可以通过自我探索发现人类没有教过的解法。

R1-Zero 就是这个论断的极端验证：没有人教它"怎么推理"，它通过试错自己学会了推理——而且推理过程展现出了类似人类的反思和纠错特征。

渠道管理类比：Day 13 我们对比了"标准操作手册"（SFT）和"只给绩效目标让员工自己摸索"（RL）。R1-Zero 就是最极端的后者——连操作手册都不给，只说"合同审核通过率要 95%以上"，然后新人居然自发发展出了一套比老手册更高效的审核方法。

创新 2：MoE 架构的成本效率极致（DeepSeek-V3）

DeepSeek-V3 用了 Mixture of Experts（MoE）架构——这个我们在 Day 24 讲 Gemini 时提过。但 DeepSeek 的 MoE 做到了更极致的效率：

指标DeepSeek-V3GPT-4（估算）差异
总参数量671B（6710 亿）~1.8T（估算）约 1/2.7
单次推理激活参数37B（仅 5.5%）~全量激活每个 Token 只用 37B 参数
训练成本~557 万美元~1 亿美元（估算）约 1/18
训练用算力2.788M H800 GPU-hours远超此数效率差距显著

MoE 的关键概念（Day 24 回顾）：

  • 把一个巨大的模型分成很多"专家子网络"
  • 每次输入只激活其中少数几个专家（DeepSeek-V3 是 671B 参数中每次只激活 37B）
  • 效果 = 拥有大模型的知识广度，但推理成本接近小模型

DeepSeek 的独特优化——Multi-head Latent Attention（MLA）和辅助损失无关的负载均衡策略——进一步压缩了 KV Cache 显存和训练时的通讯开销。

成本效率的管理类比

想象两种渠道管理模式：

模式 A（Dense Model / GPT-4 式）：全国 500 人的渠道管理团队，每个项目所有人都参与评审——能力全覆盖，但人力成本极高。

模式 B（MoE / DeepSeek 式）：全国 500 人中按专业分成 16 个专家小组，每个项目只调动 2-3 个相关小组——同样覆盖全业务线，但每个项目的实际执行成本只有 A 的 1/5。

DeepSeek 证明的是："全员上阵"不是唯一方式，"精准调动"可以用更低的成本达到近似的效果。

创新 3：蒸馏策略的规模化应用

DeepSeek 做了一个对整个行业影响深远的操作：用 R1 大模型的推理过程作为"教材"，蒸馏出一系列小模型。

蒸馏模型基座参数量效果
DeepSeek-R1-Distill-Qwen-1.5BQwen2.5-1.5B15 亿超越 GPT-4o-0513 在部分数学任务上
DeepSeek-R1-Distill-Qwen-7BQwen2.5-7B70 亿接近 o1-mini 水平
DeepSeek-R1-Distill-Qwen-32BQwen2.5-32B320 亿接近 o1 水平
DeepSeek-R1-Distill-Llama-70BLlama-3.1-70B700 亿多项基准测试超越 o1

这意味着：一个 70 亿参数的小模型——可以在你的笔记本电脑上运行——在推理任务上接近 o1。

蒸馏 = "知识蒸馏"的含义

Day 9 讲过知识蒸馏的概念："大模型教小模型，像老带新"。

DeepSeek 的蒸馏特别之处：它不只是让小模型模仿大模型的最终答案，而是让小模型学习大模型的完整推理过程——包括思维链、回溯、自我纠正等步骤。

效果：小模型学会的不只是"什么是正确答案"，而是"怎么一步步推出正确答案"——这就是为什么蒸馏后的小模型推理能力远超同尺寸的普通模型。

三、为什么选择开源？——战略逻辑拆解

开源不是慈善。DeepSeek 选择开源有清晰的战略逻辑：

逻辑 1：核心业务不依赖 AI 商业化

前面讲过——DeepSeek 的"客户"是自家的量化交易系统。开源不损害核心利益，反而：

  • 吸引全球顶尖人才（"这家公司技术太强了"→ 求职意愿）
  • 社区贡献反馈改进（bug 发现 / 应用场景探索 / 微调方案）
  • 品牌影响力 → 量化交易的合作伙伴和数据来源可能因此扩大

逻辑 2：对闭源竞争对手的"降维打击"

开源 = 瓦解闭源定价权

OpenAI 的 o1 API 定价：输入 $15 / 百万 token，输出 $60 / 百万 token。

DeepSeek-R1 API 定价：输入 ¥4 / 百万 token，输出 ¥16 / 百万 token。

而且 R1 的权重是开源的——你可以完全免费部署在自己的服务器上。

这意味着：如果一家企业原本每年花 100 万美元购买 OpenAI 的推理 API，现在可以考虑用 DeepSeek 的开源模型自部署——API 成本可能降到 1/10 甚至更低。

对于 OpenAI 来说，这不只是竞争——这是定价基础的动摇。

逻辑 3：证明一种新的 AI 发展范式

DeepSeek 开源的隐含宣言："顶级 AI 能力不一定需要顶级烧钱"。

如果这个宣言被行业接受：

  • OpenAI 的"烧钱换能力"叙事就变弱——投资人会问"你为什么需要 100 亿但别人只用 5 亿？"
  • NVIDIA 的"无限 GPU 需求"叙事就变弱——效率提升意味着同等能力需要更少的芯片
  • 闭源模型的"数据飞轮护城河"就变弱——开源社区的集体改进速度可能更快

渠道管理类比：这像一个代理商把自己最有效的获客方法论写成了公开课程免费发布——短期看"把自己的看家本领送人了"，长期看：

  • 它证明了"这个方法论不需要花大价钱请咨询公司"——打击了竞品的定价基础
  • 它吸引了大量想学这套方法论的人才加入——人才红利
  • 它的核心竞争力不是方法论本身，而是执行这套方法论的组织能力和数据积累——这些才是真壁垒

最大隐患：成本数字的真实性

DeepSeek 声称的"557 万美元训练成本"被行业广泛引用，但需要注意：

  • 这个数字只计算了最终训练运行的 GPU 小时成本——不包括前期的研究实验、架构探索、失败的训练尝试
  • 不包括数据收集和处理成本
  • 不包括团队薪资和运营成本
  • 不包括从 DeepSeek-V1 到 V3 的累积 R&D 投入

实际的"全口径研发投入"可能是公开数字的 5-10 倍以上。但即便如此，与 OpenAI 的投入量级相比仍然是显著更低的。

渠道类比：代理商说"我获客成本只要 50 元/人"——你得问清楚这是"投放成本"还是"投放+团队+物料+售后的全口径成本"。但即使全口径加上去，如果仍然只有竞品的 1/3，那核心结论不变。

启示 1：开源 vs 闭源不是信仰选择——是成本-控制-能力的三角权衡

维度闭源 API
（OpenAI / Anthropic）		开源自部署
（DeepSeek / LLaMA）
启动成本低（注册即用）中高（需要 GPU 服务器、运维团队）
长期单位成本按量计费，大量使用后总成本高固定成本为主，大量使用后边际成本极低

关键判断框架：

  • 日调用量 < 10,000 次 → 闭源 API 更划算（省运维成本）
  • 日调用量 > 100,000 次 → 开源自部署开始有成本优势
  • 涉及敏感数据（客户合同 / 财务数据 / 交易记录）→ 开源自部署安全性更高
  • 需要深度定制（特定领域术语 / 输出格式 / 推理逻辑）→ 开源 + Fine-tune
  • 快速验证 MVP → 闭源 API 先跑通，验证后再决定是否迁移

启示 3：一个更深层的行业判断

DeepSeek 不只是一个公司——它代表了一种行业趋势：AI 能力的"普惠化"。

回顾互联网历史：2000 年代初，建一个网站需要花几十万买服务器和带宽。AWS 出现后，变成了按月付费几百块钱。开源框架（WordPress/React）出现后，变成了几乎免费。

AI 正在走同一条路：
2023 年：用顶级 AI 能力 = 付 OpenAI 高价 API → 只有大公司玩得起
2025 年：DeepSeek 开源 + 蒸馏 → 顶级推理能力可以在笔记本上运行 → AI 能力的获取门槛骤降

这意味着：AI 能力本身正在快速贬值。真正的差异化将从"谁能调用最强的模型"转向"谁能用 AI 最好地解决真实问题"。

对你来说：与其纠结"选哪个模型"，不如把更多精力放在Day 20 讲的"可验证问题定义"和 Day 21 讲的"工作流设计"——因为这些是模型变便宜后依然稀缺的能力。

🧠 Checkpoint

场景：你的团队目前全用 GPT-4o API 跑 Day 21 的渠道绩效分析 Agent 工作流，每月 API 费用约 ¥15,000。老板看到 DeepSeek 的新闻后问你："我们是不是应该全切到 DeepSeek，能省一大笔钱？"你怎么回答？

A 直接全切 DeepSeek-R1 API——推理能力接近 o1，成本降 90%，没理由不切。省下的钱比什么都实在。
B 不建议切——开源模型在稳定性、服务支持、安全合规方面都不如 OpenAI 成熟。省钱不能省在核心系统上。
C 按 Worker 分层切换：Worker A/B（数据拉取和异常标记）切 DeepSeek 省成本，Worker C/D（原因分析和报告撰写）保留 GPT-4o 保质量。预计省 40-50%。
D 先花两周跑一轮对比测试——用历史数据同时跑 GPT-4o 和 DeepSeek 两条流水线，按每个 Worker 的准确率、稳定性、成本分别对比，拿数据说话再做决定。

追问：假设测试结果显示——Worker C（原因分析）用 DeepSeek-R1 的准确率是 82%，用 GPT-4o 是 87%。差 5 个百分点。但 DeepSeek 的成本只有 GPT-4o 的 1/8。你会选哪个？为什么？这 5% 的差距在什么条件下是"可接受"的，在什么条件下是"不可接受"的？

📌 知识卡片

1 DeepSeek 的独特定位：不靠卖模型赚钱
母公司幻方量化自有资金 → 不依赖 AI 商业化 → 可以无顾忌开源 + 极低定价。这种"成本中心而非利润中心"的 AI 实验室，对"靠利润续命"的闭源公司构成结构性威胁。
2 R1-Zero 验证：纯 RL 可以涌现推理能力
不给 SFT 教材、不给 CoT 范例，只靠"答案对错"的奖励信号 → 模型自发产生思维链、回溯、自我纠错。Day 13 "RL 可以超越标注者"的极端验证。
3 MoE + 蒸馏 = 成本效率的双重压缩
671B 参数但每次只激活 37B → 大模型知识+小模型推理成本。再通过蒸馏把推理能力转移到 7B/32B 小模型 → 笔记本电脑也能跑接近 o1 水平的推理。
4 开源 vs 闭源的三维判断框架
不是信仰选择——问三个问题：① 日调用量级？（>10 万次 → 开源有成本优势）② 数据敏感度？（高 → 开源自部署更安全）③ 定制深度？（需要 Fine-tune → 开源必选）
5 AI 能力正在快速普惠化
2023 年顶级 AI = 付高价 API。2025 年 DeepSeek 开源+蒸馏 → 顶级推理免费可用。真正的差异化从"调用最强模型"转向"用 AI 最好地解决真实问题"——工作流设计能力比模型选择更重要。
