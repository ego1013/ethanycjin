Day 12 · Fine-tune vs RAG vs Prompt：三种「定制」路径

什么时候用哪种？

📅 2026-04-22 Wed 📦 第一模块 · 地基篇 · Week 2 ⏱️ 预计 40 分钟
🔥 开场

你刚入职一家公司，公司给你配了一台崭新的 MacBook。开机第一天——它什么都不懂。不知道你的工作习惯，不知道公司的内部系统，不知道你常用的文件在哪里。

你有三种方式让它"变得懂你"：

第一种：花三个月"调教"它——安装各种软件、配置快捷键、训练输入法词库，让它从骨子里变成你的工具。费时费力，但一旦完成，它就是为你定制的。

第二种：不改电脑本身，而是在桌上放一个"速查手册"——每次遇到问题，先翻手册找答案。电脑没变，但你加了一层"外部知识"。

第三种：什么都不改，只是每次用的时候给它更清晰的指令——"打开那个在桌面第三个文件夹里的 Excel，用公式 X 算出 Y"。够细致的指令能让通用工具做出定制化的效果。

这三种方式，恰好对应了让大模型"变得懂你"的三条路径：Fine-tune（微调）、RAG（检索增强）、Prompt Engineering（提示工程）。

今天的核心问题：这三种方式的本质区别是什么？什么时候用哪种？为什么大部分人一上来就想 Fine-tune，但 80% 的场景其实不需要？

10 min

Why — 为什么"定制"是一个必须回答的问题？

通用模型的根本局限

回顾前 11 天：我们知道大模型通过预训练学会了"世界知识"，通过 Post-train 学会了"对话礼仪"。但它学的是互联网上的公开知识，不是你公司的内部知识。

你问 GPT-4："我们公司的渠道返利政策是什么？" 它不知道——因为你的政策文档从未出现在它的训练数据里。

你问 Claude："帮我按照我们内部模板写一份代理商评估报告。" 它不知道——因为你的模板是内部文件。

通用模型就像一个通才毕业生：智商很高、什么都懂一点，但完全不了解你的业务。 要让它真正有用，你必须解决一个问题：怎么把你的业务知识注入给它？

💡 关键洞察

这个问题之所以重要，是因为它决定了AI 落地的"最后一公里"。

技术上的 breakthrough（NTP、Attention、Scaling Law）解决的是模型"能不能"的问题。而 Fine-tune / RAG / Prompt 解决的是模型"好不好用"的问题。

大多数企业的 AI 项目不是死在模型不够强，而是死在定制路径选错了——该用 RAG 的用了 Fine-tune，该用 Prompt 的搞了一个月 Fine-tune 效果还不如好好写 Prompt。

为什么这个选择很容易做错？

因为三种路径的表面效果很相似——都能让模型"懂"你的业务。但它们的底层机制、成本结构、适用场景完全不同。就像解决"员工能力不足"这个问题：

🧬
Fine-tune
改基因
把知识写进模型参数
≈ 送员工去 MBA 进修
📚
RAG
给工具书
每次查完再回答
≈ 给员工一本操作手册
📋
Prompt
给指令
每次当面说清楚要什么
≈ 每次开会时交代清楚任务

送 MBA 培训是好，但如果问题只是"他不知道今天的会议议程"，给他一份 agenda 就够了，没必要花三个月送他去进修。

选对路径，事半功倍；选错路径，烧钱烧时间还效果差。 这是今天最核心的判断力。

20 min

What — 三种路径的本质差异

一、Prompt Engineering：改指令，不改模型

最轻量的方式。模型本身一个参数都不动，你只是在每次调用时，在上下文中提供足够的信息和指令。

Prompt Engineering 的机制

用户提问："我们渠道返利政策是什么？"

你的操作：在 Prompt 中附上政策原文

┌──────────────────────────────────────────┐
│ System Prompt：你是渠道管理助手。          │
│ 以下是公司渠道返利政策全文：             │
│ [粘贴 3000 字政策文档]                    │
│ User：返利政策是什么？                  │
└──────────────────────────────────────────┘
                     ↓
模型从上下文中找到答案，直接回答
模型参数未改变，知识来自当次输入

核心特征

维度Prompt Engineering
知识存储位置上下文窗口（临时的，用完就没了）
成本几乎为零（只是写好 Prompt）
生效时间即时
知识容量受限于 Context Window（Day 10 讲的）
适合场景知识量不大、格式/风格定制、任务指令明确
📊 类比：每次开会交代清楚

你有一个能力很强的下属。每次给他布置任务时，你把背景、目标、约束条件、输出格式都说清楚，他就能做得很好。

你没有改变他的能力，只是给了足够好的上下文。大部分时候，这就够了。

二、RAG（Retrieval-Augmented Generation）：检索增强生成

Prompt 的瓶颈很明显：Context Window 有限（Day 10 讲过，128K Token 对应大约 8 万字中文）。如果你的业务知识有上千份文档、几十万字，塞不进去怎么办？

RAG 的核心思路：不把所有知识塞进上下文，而是先检索，找到最相关的片段，只把相关片段塞进上下文。

RAG 的完整流程

准备阶段（一次性）
1. 收集所有业务文档（政策、手册、FAQ……）
2. 切成小段（每段 200-500 字）
3. 每段用 Embedding 模型转成向量
4. 存入向量数据库

查询阶段（每次调用）
1. 用户提问："Q4 返利政策变化是什么？"
2. 把问题也转成向量
3. 在向量数据库中找到最相关的 3-5 个段落
4. 把段落 + 问题一起放进 Prompt
5. 模型基于检索到的内容回答

模型参数仍未改变，但知识库可以无限大

核心特征

维度RAG
知识存储位置外部数据库（持久的，可随时更新）
成本中等（需要搭建向量数据库 + Embedding 管线）
生效时间几天到一周（搭建管线 + 灌数据）
知识容量理论无上限（数据库想存多少存多少）
适合场景知识量大、需要实时更新、需要引用来源
📊 类比：给员工配一本速查手册

你没有改变员工本人——他的技能、思维方式、判断力都没变。但你在他桌上放了一本厚厚的《渠道管理操作手册》，他遇到问题先翻手册，找到相关章节，再结合自己的判断给出回答。

手册可以随时更新（换一版新的就行），员工不需要重新培训。这就是 RAG 最大的优势：知识更新成本极低。

⚠️ RAG 不是万能的：检索质量是生死线

RAG 的效果取决于检索阶段能否找到真正相关的段落。如果检索找错了——比如用户问"Q4 返利政策"，检索系统返回的是"Q2 返利政策"——那模型会"胸有成竹地回答错误的内容"。

这比模型说"我不知道"更危险。回想 Day 6 的幻觉课——RAG 没有消除幻觉风险，只是把风险从"模型不知道"转移到了"检索不准确"。

三、Fine-tune（微调）：改模型参数

前两种方式都不改模型本身。Fine-tune 不一样——它直接修改模型的参数（权重），让知识"写进"模型的神经网络。

Fine-tune 的机制

训练阶段（一次性，但很贵）
1. 准备"问-答"训练数据（数百到数千对）
   例："Q4 返利政策？" → "根据最新政策，Q4……"
2. 用这些数据继续训练模型
3. 模型参数被修改，内化了新知识

使用阶段
用户直接问："Q4 返利政策是什么？"
模型直接从参数中回答，不需要检索或提示

模型参数已改变，知识变成了"肌肉记忆"

核心特征

维度Fine-tune
知识存储位置模型参数（永久的，但更新需要重新训练）
成本高（GPU 算力 + 数据标注 + 训练时间）
生效时间数天到数周
知识容量有限（模型参数量决定了能内化多少知识）
适合场景改变行为模式、特定领域深度适配、响应延迟敏感
📊 类比：送员工去 MBA 进修

你不只是给他一本手册，而是从根本上改变了他的知识结构和思维方式。他读了两年 MBA，学会了财务分析、战略思维、组织管理。

优点：之后遇到问题不用查手册，直接就能给出高质量判断。
缺点：花了两年时间和几十万学费。而且——如果公司业务方向变了，他的 MBA 知识不会自动更新，需要再进修。

四、三条路径的核心对比

把三种方式放在一起比：

维度 Prompt RAG Fine-tune
改了什么 输入 输入 + 外部知识源 模型本身
知识更新 改 Prompt 即可 更新数据库即可 需要重新训练
前期投入 几小时 几天~一周 几周~几个月
边际成本 每次调用要传长 Prompt 每次调用多一步检索 调用成本同普通模型
知识可追溯 ✅ 知识在 Prompt 里 ✅ 能标注来源文档 ❌ 写进参数后无法追溯
幻觉风险 低（知识就在上下文中） 中（取决于检索质量） 高（可能"过拟合"训练数据）
💡 一句话记忆法

Prompt = 开会交代清楚（临时、灵活、没有记忆）
RAG = 给一本手册（持久、可更新、但要会查）
Fine-tune = 送去进修（深刻、内化、但贵且慢）

五、核心判断框架：什么场景用什么路径？

不要背特征对比表，记住一个决策树：

🤔 第一个问题：你要解决的是"知识不够"还是"行为不对"？
知识不够 → 模型不知道你的业务数据。走 Prompt 或 RAG。
行为不对 → 模型知道相关知识，但输出的风格、格式、推理方式不符合你的要求。走 Fine-tune。
🤔 第二个问题（如果是"知识不够"）：知识量有多大？
< 5万字 → 塞进 Prompt / System Message 就行了。用 Prompt。
> 5万字 → Context Window 放不下。用 RAG。
🤔 第三个问题（如果是"行为不对"）：是格式问题还是推理能力问题？
格式/风格 → 先试Few-shot Prompt（给几个范例），80% 能解决。
推理模式 → 模型需要学会一种新的思维方式。Fine-tune。
✅ 实操黄金法则

Prompt First → RAG Second → Fine-tune Last

这是业界公认的最佳实践顺序。永远先尝试最轻量的方案，只有在轻量方案明确不够用时才升级。原因很简单：

1. Prompt 失败了 → 几小时白费，可以接受
2. RAG 失败了 → 几天白费，还好
3. Fine-tune 失败了 → 几周时间 + 几万块 GPU 费用白费，很痛

80% 的企业 AI 定制需求，用 Prompt + RAG 就能解决。 真正需要 Fine-tune 的场景比你想象的少得多。

六、真实案例对照

来看几个具体场景，验证一下决策框架：

场景 正确路径 为什么
让 AI 回答"公司 Q4 返利政策" RAG 知识不够 + 政策文档量大 + 会频繁更新
让 AI 按内部模板写代理商评估报告 Prompt 行为问题但属于格式风格 → 给几个范例即可
让客服模型回答时永远先共情再解决 Fine-tune 行为模式 + 需要贯穿每次对话 → 内化成习惯
让 AI 分析渠道数据并生成周报 Prompt + RAG 知识（数据）不够 → RAG；输出格式 → Prompt
让医疗 AI 按临床指南推理诊断 Fine-tune + RAG 需要新推理能力（Fine-tune）+ 最新指南知识（RAG）
让 AI 用粤语风格写营销文案 Prompt 风格问题 → 给几个粤语范例就能学会

注意最后两行——三种路径不是互斥的，复杂场景往往需要组合使用。 但组合的原则不变：先 Prompt，不够加 RAG，还不够再 Fine-tune。

8 min

So What — 这改变了什么？

对 AI 产品策略的三个影响

1 "AI 产品"的竞争壁垒不在模型，而在定制管线
GPT-4、Claude、Gemini——基座模型大家都能调用。真正的差异化在于：你的 RAG 管线有多好？你的 Prompt 体系有多精细？你的 Fine-tune 数据有多稀缺？ 定制能力就是产品壁垒。
2 "数据资产"的价值被重新定义
你的内部文档、操作手册、客户 FAQ、历史工单……这些以前是"沉睡的数据"。现在它们是 RAG 的燃料、Fine-tune 的训练集。拥有高质量的领域数据，等于拥有了 AI 时代的护城河。
3 AI 项目的 ROI 计算方式变了
传统的 IT 项目：花 X 万开发，上线后每年维护 Y 万。
AI 项目：Prompt 版 1 天上线花几千块，RAG 版一周上线花几万，Fine-tune 版一个月上线花几十万。 大多数 AI 项目应该从 Prompt 开始验证价值，而不是一上来就搞最贵的方案。

对你工作的实操启示

✅ 渠道管理中的定制路径选择

场景 1：代理商常见问题自动回答
路径：RAG。把所有政策文档、FAQ 灌进向量数据库，代理商提问时自动检索相关段落回答。知识更新时只需替换文档，不用动模型。

场景 2：渠道绩效周报自动撰写
路径：Prompt + 少量 RAG。用 Prompt 定义报告模板和风格，用 RAG 检索当周数据。模板在 Prompt 里，数据在 RAG 里，分工明确。

场景 3：让 AI 学会"像老渠道经理一样"判断代理商风险
路径：Fine-tune。这不是知识问题（政策都知道），而是判断模式问题。需要用大量历史案例（"这种情况→高风险/低风险"）训练模型内化经验。

💡 一句话总结

Fine-tune 改的是模型的"大脑结构"，RAG 改的是模型的"信息来源"，Prompt 改的是模型的"任务指令"。

三者不互斥，但有严格的优先级：Prompt First → RAG Second → Fine-tune Last。

选对路径的关键判断只有两步：第一步，问题是"知识不够"还是"行为不对"？第二步，知识量能塞进上下文吗？

✅ 今日 Checkpoint

场景：你的团队想让 AI 自动审核代理商提交的"费用报销单"——检查金额是否合规、附件是否齐全、审批流是否正确。目前人工审核每月处理 2000 单，平均每单 15 分钟。团队预算有限，老板希望一个月内上线。

你会选哪种定制路径？

A Fine-tune。用 2000 份历史报销单和审核结论训练模型，让它"学会"审核逻辑。一劳永逸，以后都不用人工了。
B RAG。把报销规则手册、合规标准、审批流程文档灌进知识库，每次审核时检索相关规则再判断。
C Prompt。把报销规则和审核 checklist 直接写进 System Prompt，配合几个审核范例（Few-shot），让模型每次对照 checklist 逐项检查。
D 先拆解"审核"到底包含几类判断：金额合规是规则匹配（Prompt 够用）、附件齐全需要多模态能力（看图）、审批流检查是业务逻辑（可能需要 RAG 查组织架构）。按子任务分别选路径，一个月先上最容易的部分。

⚡ 追问：假设你选择先上 Prompt 方案做 MVP，一个月后发现准确率是 85%。要把准确率提到 95%，你会沿着哪条路升级？升级的成本大概是多少量级（千元/万元/十万元）？

🎯 明日悬念

今天讲了三种"定制"路径。其中 Fine-tune 我们只讲了表面——"修改模型参数"。

但 Fine-tune 内部其实有一个更深层的分歧：SFT（监督微调） 和 RL（强化学习）。

SFT 是"照着答案学"——给它标准答案，让它模仿。
RL 是"给奖惩信号，让它自己摸索"——不告诉它答案，只告诉它做对了还是做错了。

这两种训练方式，培养出来的模型"性格"完全不同。一个像流水线工人——稳定、标准、可预测；另一个像独立思考者——可能更聪明，但也可能更难控制。

Day 13，我们聊 SFT vs RL：特化与泛化的根本差异。

📌 知识卡片

1 三种路径改的东西不同
Prompt 改输入指令（不碰模型），RAG 改信息来源（加外部知识库），Fine-tune 改模型参数（修改神经网络权重）。三者不互斥，可以组合使用。
2 黄金优先级：Prompt First → RAG Second → Fine-tune Last
永远先试最轻量的方案。80% 的企业 AI 定制需求用 Prompt + RAG 就能解决。Fine-tune 是重武器，只在需要改变模型"行为模式"或"推理方式"时才动用。
3 核心判断只需两步
第一步：问题是"知识不够"（→ Prompt/RAG）还是"行为不对"（→ Fine-tune/Prompt）？第二步：知识量能塞进上下文吗？能 → Prompt，不能 → RAG。
4 RAG 的核心风险是检索质量
RAG 没有消除幻觉，只是将风险从"模型不知道"转移到"检索不准确"。检索阶段找错了段落，模型会"胸有成竹地回答错误内容"，比不回答更危险。
5 Fine-tune 的知识不可追溯、不可即时更新
知识写进参数后，无法标注"这个回答来自哪份文档"，也无法像 RAG 那样换一份文档就更新知识。对于频繁变化的业务知识，Fine-tune 是最差选择。

🔗 前序知识连接

← Day 2 Day 2 讲了 Embedding——把文字变成向量。RAG 的核心管线正是建立在 Embedding 之上：文档切段 → Embedding → 存入向量数据库 → 检索时用向量相似度匹配。没有 Day 2 的 Embedding 概念，RAG 无法理解。
← Day 3 Day 3 讲了 Pre-train vs Post-train。Fine-tune 本质上就是一次轻量级的 Post-train——在已有基座模型的基础上，用你的数据再训练一轮。它不是从零开始，而是"站在巨人肩膀上的微调"。

← Day 11 Day 11 讲了多模态。多模态 + 定制路径的组合正在成为新趋势：多模态 RAG（图片+文档混合检索）、多模态 Fine-tune（让模型认识你的产品照片）、多模态 Prompt（直接在上下文中放图片做 Few-shot）。
