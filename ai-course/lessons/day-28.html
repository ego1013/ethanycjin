一、底层详解——分析一家 AI 公司/模型的标准流程

当一个新模型或新公司出现在你视野中（"听说 X 很厉害"），用以下流程建立结构化认知：

底层分析 · 四步标准流程

Step 1：定位它在光谱上的位置

五种竞争策略类型（Day 27）——综合领先 / 信任壁垒 / 生态捆绑 / 单点极致 / 成本颠覆。新出的 AI 公司/模型属于哪一种？这一步 30 秒就够。

Step 2：七维度快速扫描

战略赌注 / 护城河来源 / 商业化压力 / 路径风险 / 锁定程度 / 成本弹性 / 能力匹配度。不需要每个都深挖——先全面扫一遍，再对关键维度做深入分析。

Step 3：识别差异化的持久性

  • 创业公司三问法（Day 25）：差异化能否 3 秒说清？会被追平吗，多久？窗口期后靠什么？
  • 开源 vs 闭源（Day 26）：调用量级 / 数据敏感度 / 定制深度 → 开源还是闭源对你更有利？

Step 4：输出结论——"一句话画像 + 一张评分卡"

一句话画像示例："Qwen-3 = 综合领先型的中国挑战者，推理能力接近 GPT-4o，成本低 60%，但生态和企业信任积累仍早期。"

用这个流程练一下——假设明天出了一家叫 "NovaMind" 的新 AI 公司，宣称"在医疗影像 AI 领域准确率超过 GPT-4o 30%，价格只有 1/5"。你会怎么分析？

Step分析
1. 光谱定位单点极致——垂直领域（医疗影像）+成本优势=Kimi 式 + DeepSeek 式的混合
2. 七维度重点护城河：医疗数据壁垒几何？（医疗数据获取极难 → 可能是真壁垒）
锁定：API 还是私有协议？（影响切换成本）
商业化：医疗 AI 的付费意愿和合规成本？
3. 差异化持久性3 秒说清：✅ "医疗影像比 GPT-4o 准 30%"
会被追平吗：🟡 看数据壁垒——如果其数据来自独家合作医院，窗口期可能 2-3 年
窗口期后：靠什么？客户关系？合规认证？数据飞轮？
4. 一句话画像"NovaMind = 医疗影像的 Kimi——单点极致的垂直赌注，窗口期取决于数据壁垒的独占性"

注意——整个分析不需要了解它的技术细节。你用的是结构化的判断框架，而不是记忆某个模型的参数表。这就是"操作系统"的价值：无论来什么新公司新模型，你都能用同一套流程快速定位。

二、中层详解——从分析到选型的决策流程

有了底层分析产出的"供应商画像"，接下来做选型决策。这里直接复用 Day 27 的三步选型法，但加一个关键升级：决策树化。

中层决策 · 选型决策树

面对"该用什么 AI"这个问题时，按以下顺序逐级判断：

🔍 第一关：需不需要 AI？

回溯 Day 20（可验证性）—— 这个任务有明确的验收标准吗？AI 做和人做的净效率增益是正的吗？
→ 如果验收标准模糊或者验证成本 > 节省的执行成本 → 不用 AI，用人

🔍 第二关：需不需要换模型/供应商？

当前方案有没有明确的"痛点"？性能不够？成本太高？合规风险？
→ 如果没有明确痛点 → 不换。"新模型发布"不是换的理由，"当前方案有 Bug"才是。

🔍 第三关：怎么换？

Day 27 三步选型法 —— 定义子任务 → 匹配供应商 → 加权成本风险
+ 风险对冲矩阵 —— 关键环节保留 Fallback，不把 >50% 押在同一家

最常见的判断错误

在你的工作中，最大的风险不是"选错了模型"，而是以下三种判断失误：

  1. "新的一定更好"综合症——GPT-5 出来就想换。但你的 Worker A 只是做数据格式化，GPT-4o-mini 就够了，GPT-5 贵了 3 倍但对这个环节几乎没提升。（回溯 Day 22：OpenAI 的"最强"是整体最强，不是每个子任务都最强）
  2. "别人用了我们也要用"跟风——竞争对手用了 Claude 做合规审核，但你们的合规需求可能完全不同。（回溯 Day 27：能力匹配度 > 综合排名）
  3. "先建再想"的工程冲动——直接开始搭系统，没有先验证核心环节是否可行。（回溯 Day 27 Checkpoint 的 D 选项：先定义 MVP 验证什么）

渠道管理中你绝不会因为"听说某个代理商今年很猛"就换掉现有的合作伙伴。AI 选型应该有同样的纪律。

三、顶层详解——趋势预判与策略调整

底层和中层解决的是"当前时点的最优选择"。顶层解决的是"这个选择半年后还对吗"。

Day 27 给出了三大趋势：能力趋同 / 成本暴跌 / 差异化转移。但趋势本身不够——你需要知道趋势对你的具体影响和触发调整的信号。

趋势对你的含义触发调整的信号调整动作
能力趋同
模型差距缩小到 5-10%		 "谁最强"越来越不重要，成本和集成便利性成为主要决策因素 你当前用的模型和替代模型在你的具体任务上差距 < 5% 开始考虑切换到更便宜或集成更方便的方案
成本暴跌
2 年降 50 倍		 之前因为成本放弃的用法现在可能划算了；AI 从"奢侈品"变"基础设施" 某个你之前计算过"不划算"的场景，API 成本降了 >80% 重新评估那些之前被否决的 AI 应用场景
差异化转移
从模型 → 生态/信任/工作流		 工作流设计能力比模型选择更重要——你的竞争力在于"怎么用"而非"用什么" 同行用了和你一样的模型，但效果明显更好或更差 投资在工作流设计和优化上，而非追逐最新模型
顶层的运行频率

底层分析是按需触发的——有新公司/新模型出现时做。
中层决策是项目驱动的——有新需求或现有方案出问题时做。
顶层扫描应该是定期执行的——建议每季度花 1-2 小时做一次"AI 环境扫描"。

和你的渠道管理节奏完全一样：代理商调研随时做、选型项目制推进、市场大盘季度复盘。

四、三层联动——用开场的三个问题跑一遍

回到开场的三个问题，用完整的操作系统来回答：

问题 1："Qwen-3 强 15%，要不要切？"

顶层：能力趋同趋势下，15% 的基准测试差距实际业务影响可能只有 3-5%
中层：决策树 → 第二关：当前方案有明确痛点吗？如果没有 → 不换。如果有 → 第三关：哪个子任务痛？只换痛的环节
底层：对 Qwen-3 做四步分析 → 它的"强 15%"强在什么维度？推理？多模态？如果强在推理但你的痛点是成本 → 不匹配

结论模板："Qwen-3 的 15% 提升在 [X] 维度，我们的瓶颈在 [Y] 维度。如果 X≠Y，不急着切。如果 X=Y，先在痛点环节做 A/B 测试，验证实际业务提升后再决定。"

问题 2："竞争对手用 Claude 做合规审核，跟不跟？"

顶层：差异化转移趋势 → 竞争力在于"怎么用"而非"用什么"
中层：决策树 → 第一关：我们需要 AI 做合规审核吗？（验证成本 vs 人工成本）→ 如果需要 → 第三关：我们的合规需求和竞争对手一样吗？
底层：Claude 在合规场景的确有结构性优势（Day 23：Constitutional AI + 规则遵循），但"别人用了"不是理由，"我们也有这个痛点"才是

结论模板："合规审核场景 Claude 确实有优势（Day 23），但我们先要确认：① 合规审核是我们的业务痛点吗？② 我们的合规需求具体是什么类型？③ 现有方案的缺口在哪？——先有诊断再有处方。"

问题 3："预算砍 30%，怎么降？"

顶层：成本暴跌趋势 → 半年前的价格不代表现在的价格，先查最新报价
中层：三步选型法逆向操作 → 按子任务查当前成本 → 找"贵但可降级"的环节（Day 27 五条规则的逆向）
底层：Worker A/B 是数据处理类 → 最适合降级到更便宜的模型（DeepSeek）；Worker C 是复杂推理 → 不能降级（降了质量会崩）；报告撰写 → 可以换成 DeepSeek + 人工润色

结论模板："降本优先级：① 先换 Worker A/B 到 DeepSeek（省 ~60%，质量影响极小）② 报告生成环节换模型 + 加人工终审（省 ~40%，质量靠人兜底）③ Worker C 推理环节不动（这是核心价值环节）。总计可省 35-45%。"

发现了吗？

三个完全不同的问题，用的是同一套操作系统——先看顶层趋势定方向，再走中层决策树，需要时调用底层分析做信息补充。

这套系统的价值不在于"记住了五家公司的特点"（这些信息半年后就过时了），而在于你建立了一个可以处理任何新信息的判断结构。就像你不需要记住每个代理商的具体数据，但你清楚地知道"评估代理商该看什么维度、怎么做选型决策、什么时候该换"。

操作系统的保质期

一个诚实的提醒——这套操作系统里不同部分的保质期不同：

三层架构 🔴 3-5 年
七维度框架 🔴 2-3 年

越靠近底部的内容更新越快——GPT-5 出来后 Day 22 的 OpenAI 分析就过时了，但你用来分析 OpenAI 的方法不会过时。这就是为什么我们花大量时间在框架和方法上，而非背诵公司参数。

核心一句话

第三模块前半程（Day 22-28）的全部价值，浓缩成一句话：

你不需要追踪每个模型的最新版本——你需要一套判断任何版本的操作系统。

这和渠道管理的终极认知完全一致——你不需要了解每个代理商的每月数据细节，你需要一套评估任何代理商的标准流程。有了流程，换人不影响决策质量。

🧠 Checkpoint

场景：周一早会。技术负责人兴奋地说："Llama-4 开源了，多项基准测试超过 GPT-4o，而且完全免费。我建议我们把所有 AI 模块都切换到 Llama-4 自部署，一年省几十万 API 费。"

CTO 看向你："你怎么看？"

A 支持。开源免费 + 基准测试超过 GPT-4o = 没有理由不切。省下来的钱可以投入更多功能开发。越早切越好，晚了竞争对手先切了。
B 反对。"所有模块都切"风险太大。我们现在的方案跑得好好的，没必要为了省钱冒稳定性风险。等半年看看别人踩完坑再说。
C 部分同意。可以让 Worker A/B（数据处理环节）先试切 Llama-4，跑两周看效果。Worker C/D 暂不动，因为推理和报告生成环节对质量敏感。
D 回到三个前置问题：① "超过 GPT-4o"超在什么维度？和我们的关键环节匹配吗？② 自部署的运维成本（GPU 服务器 + 团队精力）算进"省下的钱"了吗？③ 当前方案的具体痛点是什么——是成本？还是性能？如果是性能，切成免费的未必解决问题。

追问 1：假设技术负责人回答说"基准测试在推理、编程、数学三个维度超过 GPT-4o 约 10%，多模态和中文能力略弱"——这个信息会怎么影响你的判断？你会重点关注哪个维度，为什么？

追问 2："一年省几十万"听起来很多。但请估算一下：自部署一个 70B 参数开源模型需要什么配置的 GPU 服务器？月租大概多少？加上运维人力，"省几十万"还成立吗？

Day 29：AI产品设计原则(1)：长文本产品设计 — 为什么大部分"能读整本书"的产品其实很糟糕？

📌 知识卡片

1 三层判断操作系统
底层（公司/模型分析：七维度+四步流程）→ 中层（选型决策：三步选型法+决策树+风险对冲）→ 顶层（趋势预判：三大趋势+触发信号+调整动作）。三层联动才是完整判断力。
2 底层四步分析流程
① 光谱定位（五种策略类型取其一）→ ② 七维度快速扫描（重点 2-3 个维度深挖）→ ③ 差异化持久性判断（3 秒说清/追平速度/窗口期后靠什么）→ ④ 输出一句话画像+评分卡。
3 中层决策树三关
第一关：需不需要 AI？（可验证性+净效率增益）→ 第二关：需不需要换？（有明确痛点才换，"新发布"不是理由）→ 第三关：怎么换？（三步选型法+风险对冲矩阵）。
4 顶层三大趋势的行动指引
能力趋同 → 成本和便利性成为主因；成本暴跌 → 重新评估之前被否决的场景；差异化转移 → 投资工作流设计而非追逐模型。每季度做一次 AI 环境扫描。
5 操作系统的保质期分层
三层架构（3-5 年）> 七维度框架（2-3 年）> 三步选型法（1-2 年）> 五条规则（6-12 月）> 具体公司结论（3-6 月）。越上层越持久——方法不会过时，结论会。
