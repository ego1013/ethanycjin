🔥 开场

你有没有遇到过这种情况——

你在 ChatGPT 里输入"帮我写个渠道分析报告"，回来的东西泛泛而谈、不痛不痒，全是正确的废话。

然后你看到网上有人用同一个模型，输出了一份结构清晰、数据详实、角度犀利的分析。你的第一反应是什么？"这人用了什么咒语？"

但这里有个反直觉的事实：Prompt 工程不是「咒语学」，是「需求规格说明书的写法」。你在工作中天天做的事情——写需求、给下属派任务、向老板汇报——本质上和写 Prompt 是同一件事。

今天这节课会告诉你：为什么这个类比成立，以及怎么把你已有的管理技能直接迁移到 AI 协作中。

10 min

Why — 为什么 Prompt 是一切应用的起点？

回到 Day 1：模型只看到你给的上下文

还记得 Day 1 的核心心智模型吗？大模型做的事情只有一件：基于上下文，预测下一个 Token 的概率分布。

这意味着一件至关重要的事——

💡 核心洞察

模型输出的质量上限，取决于你输入的质量。

大模型不会"猜"你想要什么。它没有读心术。它只能从你给的文字中提取所有可用信息，然后在概率空间里找到"最可能的续写"。

你给它"帮我写个报告"，它的概率空间里全是泛泛的报告模板。
你给它"你是一个有 10 年渠道管理经验的分析师，请针对华东区代理商 Q1 出货量下降 15% 的现象，从市场环境、代理商能力、竞品动作三个维度分析根因，用数据说话"——它的概率空间被大幅收窄到了一个专业领域，输出质量会截然不同。

这不是"模型变聪明了"——它还是同一个模型。是你的输入质量改变了它的概率分布形状。

类比：给新来的实习生派活

你刚招了一个实习生。高材生，聪明，学习能力强——但他对你的业务一无所知。

你有两种派活方式：

❌ 模糊派活
"帮我看看华东区的数据，
整理一下。"

实习生会怎样？→ 漫无目的地翻数据，产出一堆你不想看的东西，还花了两天时间。

⚡
✅ 精确派活
"请分析华东区 Q1 出货量同比
下降 15% 的原因。
- 维度：市场/代理商/竞品
- 数据源：SAP 出货表 + 月报
- 产出：1 页 PPT + 3 条建议
- 今天下午 4 点前给我初稿"

实习生会怎样？→ 方向明确，效率高，产出接近你的预期。

大模型就是那个实习生。 它能力很强（相当于同时精通所有领域的多面手），但它对你此时此刻的具体需求一无所知。你不说清楚，它就只能给你一个"平均数"般的通用回答。

🔑 这个类比的关键

你不会觉得给实习生写清晰的任务说明是"念咒语"。你知道那是管理者的基本功——越精确的指令，越高效的产出。

Prompt 工程是完全同样的事。你在管理一个"超级实习生"——能力极强但零上下文。你的管理能力，直接等于你的 Prompt 能力。

为什么这个技能的半衰期是 🟡 中？

坦率说，Prompt 工程的具体技巧（比如什么格式效果好、加不加分隔符之类）会随着模型升级而变化——GPT-5 可能不需要你费力解释的东西，GPT-3.5 必须手把手教。

但 Prompt 工程的底层逻辑——如何把模糊需求转化为精确规格——这是一个永不过时的元能力。它和你写需求文档、设计 KPI、给团队开任务会的能力是同构的。

所以今天我们重点讲逻辑，不死记技巧。技巧会过时，逻辑不会。

20 min

What — Prompt 工程的底层逻辑与五要素框架

第一层理解：Prompt 在做什么？

从 Day 2 的知识出发，我们知道模型的输出是从一个概率分布中采样得到的。Prompt 的作用是什么？

【没有 Prompt 约束】
模型面对的概率空间：100% 开放 → 所有可能的续写都有概率
↓ 输出质量 ≈ "互联网平均水平"

【精确 Prompt】
模型面对的概率空间：被约束到特定领域 + 特定格式 + 特定角色
↓ 输出质量 ≈ "该领域专家的合格产出"
📐 Prompt 的数学直觉

你可以把 Prompt 理解为一个概率空间的过滤器。

没有 Prompt → 模型在所有可能的回答中做均匀采样 → 大概率出来一个"平庸但安全"的回答。

有精确 Prompt → 模型的概率分布被大幅重塑——不相关的 Token 概率趋近于零，相关的 Token 概率被放大 → 输出集中在你想要的范围里。

这和 Day 5 的 Temperature 不同——Temperature 调的是"分布的尖锐程度"，Prompt 调的是"分布本身的形状"。一个是调旋钮，一个是换赛道。

第二层理解：五要素框架（CRISP）

好的 Prompt 和好的需求文档有完全相同的结构。我把它总结为 CRISP 五要素——每一个你在工作中都用过：

C · CONTEXT

① 上下文：你是谁？我是谁？场景是什么？

工作类比：你给新来的人派活，第一件事是什么？——介绍情况。"我们部门管华东区 200 家代理商，上季度出货量掉了 15%，老板要我们出分析报告。"

Prompt 等价物：你是一位有 10 年经验的渠道管理分析师。背景：我们负责华东区 200 家代理商的绩效管理，Q1 出货量同比下降 15%。

为什么重要：上下文决定了模型"以谁的身份"来输出。没有上下文的模型就是一个没有背景知识的通才——它什么都知道一点，什么都不精。给了角色和场景，它的概率分布就被锚定到了那个领域的专业语料上。

R · ROLE & RULES

② 角色与规则：期望什么行为标准？

工作类比：你不只告诉实习生"去分析"，你还会说"数据要注明来源，不确定的结论用'可能'措辞，不要给没有依据的建议。"

Prompt 等价物：要求：所有数据点必须标注来源；不确定的推断需明确标注"假设"；只给可执行的建议，不给空泛的方向。

为什么重要：这是在设置行为边界——告诉模型"什么该做、什么不该做"。没有规则的模型会倾向于"过度满足"（Day 4 的 Reward Hacking 遗产），给你一堆看起来漂亮但实际空洞的内容。明确的规则让它知道"在哪里说不"。

I · INPUT

③ 输入素材：给它什么信息来工作？

工作类比：你不会让实习生自己去找数据。你会说"SAP 出货表在共享盘 XX 路径，月报在 YY，竞品情报在 ZZ。"

Prompt 等价物：直接把关键数据贴进 Prompt，或者指定信息来源。以下是华东区 Q1 的出货数据：[表格]

为什么重要：这和 Day 12 的 RAG 概念直接相关——模型自己"记忆"的知识可能不够新、不够准，但你在 Prompt 里提供的信息它能100% 看到。把关键数据喂进去，是最简单直接的"注入知识"方式。

S · SPECIFICATION

④ 输出规格：要什么格式、什么长度、什么结构？

工作类比：你一定对实习生说过——"不要给我 10 页 Word，给我 1 页 PPT，三条核心结论加数据支撑。"

Prompt 等价物：输出格式：先给 3 条核心结论（各一句话），再给每条结论的数据支撑（不超过 3 个数据点），最后给 2 条可执行建议。总计不超过 500 字。

为什么重要：大模型的默认行为是"尽可能面面俱到"——这是 RLHF 训练的结果（Day 4），用户偏好详细的回答，模型就学会了"宁可多说不可少说"。明确的格式约束是对抗这种倾向的最有效武器。

P · PERSONA CHECK

⑤ 验收标准：怎么判断产出合格？

工作类比：你收到实习生的初稿，你会用什么标准判断？——"数据对不对、逻辑通不通、建议能不能落地、老板看了会不会满意。"

Prompt 等价物：请在给出回答后，自查以下三点：(1) 所有数据点是否有来源？ (2) 结论和数据之间是否有因果关系？ (3) 建议是否具体到可以直接执行？如果不满足，请自行修正。

为什么重要：这是自检机制——让模型在输出前对自己做一次"质量审计"。这个方法效果远超你的直觉。原因在于：模型在生成"自检回答"时，相当于在做一次二次推理——它的上下文里多了自己之前的输出，可以用它来"回头看"是否自洽。

💡 CRISP 框架与需求文档的对照

Context（上下文）→ 项目背景
Role & Rules（角色与规则）→ 验收标准与约束条件
Input（输入素材）→ 参考资料与数据来源
Specification（输出规格）→ 交付物定义
Persona Check（验收标准）→ QA 自检清单

你写过多少份需求文档？——你就有多少年的 Prompt 工程经验。

第三层理解：一个真实的对比实验

让我们拿一个你工作中的真实场景来做对比——"代理商绩效下滑分析"：

❌ 新手 Prompt
帮我分析一下代理商
绩效下滑的原因。
→
✅ CRISP Prompt
【C·上下文】
你是一位渠道管理高级分析师。
我负责华东区 200 家代理商的
绩效管理。

【R·角色与规则】
分析必须数据驱动，每条结论
引用至少 1 个数据点。
不给空泛建议，只给可执行动作。

【I·输入素材】
Q1 数据：出货量同比-15%，
其中 Top 20 客户-8%，
腰部客户-22%，尾部客户-5%。
行业大盘同比-3%。

【S·输出规格】
产出：3 条核心发现 + 2 条建议，
各配 1 行数据支撑。
总计 300 字以内。

【P·自检】
输出后自查：结论和数据是否
一一对应？建议是否可直接执行？

右边这个 Prompt 看起来长了很多——但它做的事情和你给下属写任务说明完全一样。区别只是对象从人变成了模型。

实际效果差异有多大？

维度 新手 Prompt CRISP Prompt
输出长度 800-1200 字（多数是废话） 250-350 字（精准命中）
数据引用 通用统计，没有具体数字 直接引用你给的数据
建议质量 "建议加强沟通" 级别 "腰部客户需专项拜访计划" 级别
可用性 需要大幅改写才能用 稍作调整即可汇报
耗时 写 Prompt 10 秒 + 改输出 30 分钟 写 Prompt 3 分钟 + 微调 5 分钟
⚠️ 常见误区

"Prompt 越长越好？" —— 不是。长度不重要，信息密度才重要。一个 30 字的精确 Prompt 可以好过一个 500 字的啰嗦 Prompt。关键是：你给的每一句话都在缩窄模型的概率空间——如果一句话不能帮模型"排除错误方向"，那它就是噪音。

"要背 Prompt 模板？" —— 不需要。模板会过时，原理不会。你只需要内化 CRISP 五要素的思维方式，具体表达可以根据场景灵活调整。就像你不需要背"任务分配模板"来给下属派活——你知道该说什么，自然就说出来了。

第四层理解：Prompt 工程的进阶技巧（Three Big Levers）

CRISP 是基本功，在此之上有三个进阶杠杆：

杠杆 1：Few-shot Examples（范例学习）

你给实习生派活的时候，如果任务复杂，你会怎么做？——给一个好的样例。"上次张三做的那个报告，你参考那个格式。"

对模型也一样。在 Prompt 里给 1-3 个期望输出的范例，模型会强烈"模仿"你的格式和风格。这比用文字描述格式高效得多——因为模型在训练时就被优化成了一个强大的模式模仿器（Day 1 的 NTP 本质）。

杠杆 2：Step-by-step（分步拆解）

复杂任务不要让模型一步到位。你不会让实习生"直接给我一份完美的分析报告"——你会说"先梳理数据，再找异常点，最后写结论"。

在 Prompt 里给出明确的步骤，模型会按步骤逐步推理，而不是跳到结论。这和明天要讲的思维链（CoT）直接相关——本质上你在帮模型构建一条更高质量的推理路径。

杠杆 3：Negative Prompting（负面约束）

告诉模型不要做什么，有时候比告诉它要做什么更有效。"不要用模糊措辞""不要给超过 3 条建议""不要编造数据"。

原理也回到了 Day 4——RLHF 训练让模型有"讨好用户"的倾向，负面约束是显式地告诉它"在这些方向上不需要讨好我"。

🧰 三个杠杆的成本-收益排序

投入产出比最高 → 最低：

① Negative Prompting（加一句话就能避免最常见的问题）
② Step-by-step（分 3 步能让复杂任务质量提升 30-50%）
③ Few-shot Examples（效果最强但准备成本最高——你得先有好样例）

和管理一样：先画红线，再定流程，最后给模板。

8 min

So What — 这改变了什么？

一、你已经是 Prompt 工程师了

如果你在工作中做过以下任何一件事，你就已经在做 Prompt 工程：

你的工作场景 等价的 Prompt 技能
给新员工写入职说明 Context + Role 设定
给下属写绩效考核标准 Rules + Specification
把客户需求转化为产品 PRD 把模糊意图转化为精确 Prompt
给实习生一个参考报告的样例 Few-shot Examples
对外包团队说"不要做 XX" Negative Prompting
把大项目拆成周计划 Step-by-step 分步拆解

认识到这一点很重要——因为你不需要"从零学起"。你只需要把已有的管理能力"翻译"一下，应用到人机协作的新场景里。

二、对渠道管理工作的直接影响

几个你下午就可以试的 CRISP 应用场景：

1 代理商月报自动分析
把代理商的月报原文贴进 Prompt（I · 输入），设定分析维度和输出格式（S · 规格），加上"不要编造没有出现在原文中的数据"（Negative Prompting）。

预期效果：原本需要 30 分钟手工梳理的月报，5 分钟出初稿。你只需要做最终判断和修正——把时间花在"判断"而非"整理"上。
2 渠道政策 FAQ 自动回复草稿
给模型你们的渠道政策文档（I · 输入），设定角色为"渠道支持专员"（C · 上下文），规则是"只回答文档中有明确依据的内容，没有把握的说'请联系渠道经理确认'"（R · 规则）。

预期效果：这就是 Day 12 讲的 Prompt + RAG 的最简版本。不需要任何技术搭建，直接在 Chat 界面就能用。
3 竞品情报结构化整理
把收集到的竞品碎片信息贴进去，用 Step-by-step 让模型"先分类 → 再比较 → 最后给出差异化分析"。加一个 Few-shot（给一个你认为好的竞品分析范例）。

预期效果：从"信息散点"到"结构化洞察"的转化效率提升 5-10 倍。

三、更深一层的思考

🔭 Prompt 工程的未来

现在的 Prompt 工程还比较"手工"——你需要自己想清楚五个要素然后写出来。

但趋势很明确：模型正在变得越来越会"追问"。Claude、GPT-4o 已经会在你给出模糊指令时主动问你"你想要什么格式？""受众是谁？"——它们在用自己的能力帮你补全 CRISP 框架的缺失部分。

这意味着：未来你不需要写完美的 Prompt——但你需要能判断模型的追问是否在点子上。这又回到了管理能力：好的管理者不一定亲自写需求文档，但他一眼就能看出需求文档哪里不对。

Prompt 工程的终极形态不是"写 Prompt"，而是"管理 AI 的工作质量"。

✅ Checkpoint · Day 15

场景：你需要让 AI 帮你准备明天向老板汇报的"Q1 华东区代理商绩效下滑分析"。以下哪种做法最有效？

A 直接说"帮我分析华东区代理商绩效下滑"，然后对输出不满意的部分再追问修改，通过多轮对话逐步逼近想要的结果。
B 从网上找一个"最强分析 Prompt 模板"，填入自己的数据，直接发给 AI。
C 用 CRISP 框架：设定角色（渠道分析师）、给规则（数据驱动）、贴数据、定格式（3 条核心发现 + 2 条建议）、加自检。一次发出，获得高质量初稿。
D 先花 5 分钟想清楚"老板最关心什么"——是整体数据、还是头部客户风险、还是竞品威胁？然后针对老板的关注点用 CRISP 框架写 Prompt，而不是泛泛分析。最后让 AI 自检"如果我是一个关注 XX 的老板，这个分析是否回答了我的核心疑问"。

⚡ 追问：如果你选了 C 或 D，请估算一下——用 CRISP 框架写 Prompt 大概需要几分钟？和你直接自己写这份分析相比，总耗时（写 Prompt + 审核修改输出）大概能节省多少？给一个百分比。

🎯 明日预告：Day 16 · 思维链（CoT）与推理增强

今天你学会了怎么给 AI"派活"——告诉它做什么、怎么做。

但有一类问题，光给指令不够——你需要让 AI "想清楚再说"。

比如：一个代理商的返利政策涉及 5 个条件的组合判断，模型直接给答案经常出错。但如果你让它"先列出所有条件 → 逐一判断是否满足 → 再给结论"——准确率能从 60% 飙升到 90%。

这就是思维链（Chain of Thought）。它不是让模型"更聪明"，而是让模型把推理过程展开——像你要求下属"别直接告诉我结论，先把推导过程写出来"。

Day 16 将揭示：为什么"展开推理步骤"能大幅提升准确率，以及这对模型的概率分布意味着什么。

1 Prompt = 概率空间的过滤器
Prompt 不是"咒语"，是对模型概率空间的约束和重塑。精确的 Prompt 把不相关的 Token 概率压趋于零，让模型的输出集中在你需要的范围内。Temperature 调的是分布的尖锐程度，Prompt 调的是分布本身的形状。
2 CRISP 五要素 = 需求文档结构
Context（上下文/项目背景）→ Role & Rules（角色与规则/约束条件）→ Input（输入素材/参考资料）→ Specification（输出规格/交付物定义）→ Persona Check（验收标准/QA 自检）。你写过需求文档，就会写 Prompt。
3 三大进阶杠杆：红线 → 流程 → 模板
① Negative Prompting（画红线，投入产出比最高）→ ② Step-by-step（定流程，复杂任务必备）→ ③ Few-shot Examples（给模板，效果最强但准备成本最高）。顺序和管理一样：先画红线，再定流程，最后给模板。
4 管理能力 = Prompt 能力
好的管理者给下属的任务说明精确、有约束、有验收标准。好的 Prompt 工程师给模型的指令精确、有约束、有自检清单。两者是同构的。你不需要"从零学起"Prompt 工程——你只需要把已有的管理技能迁移到人机协作场景。
5 Prompt 工程的终极形态：不是写 Prompt，是管理 AI 工作质量
模型正在变得越来越会"追问"和"自补全"——你不需要写完美的 Prompt，但你需要能判断 AI 的理解是否准确、输出是否达标。这是从"操作者"到"管理者"的跃迁，和你管理团队的能力完全一致。
