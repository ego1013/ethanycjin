Harness 革命：AI 不是输在脑子，而是输在"操作系统"

递归自我改进（RSI）的真正起点不是改写模型权重——当前 AI 还没聪明到能改好自己。翁荔的论断是：近期最可行的路径，是让 AI 先优化那层决定它如何思考、调用工具、验证结果的"运行系统"——Harness。改进"获取答案的机制"，比改进答案本身更紧迫。
核心来源：
Lilian Weng (前 OpenAI 安全 VP，Thinking Machines Lab 联创) — Harness Engineering for Self-Improvement, 2026-07-04
DeepSeek 崔添翼 — 转发附议，强调 Harness 自进化与模型自进化同等重要
I.J. Good (1965) — "Speculations Concerning the First Ultraintelligent Machine"
Eliezer Yudkowsky (2008) — "Recursive Self-Improvement"

🧩 深度解读

当我们谈论"AI 自我进化"时，默认的画面通常是科幻式的：一个超级智能模型坐在服务器里，改写自己的权重，一代比一代强。这个画面来自 I.J. Good 1965 年的经典定义——超级智能机器能够设计出更好的机器来改进自身。

但翁荔（Lilian Weng）——前 OpenAI 安全 VP，现在 Thinking Machines Lab 的联合创始人——在最近一篇万字长文中，提出了一个完全不同的判断：近期最可行的 RSI 路径，不是让模型直接改写自己的"大脑"，而是让它先优化那层围绕大脑的"运行系统"——Harness。

什么是 Harness？简单说，它是基础模型周围的编排层：决定模型如何思考与规划、如何调用工具与行动、如何感知与管理上下文、如何存储产物、如何评估结果。用翁荔的话说："模型与真实世界情境之间的那一层，其重要性似乎不亚于模型本身的原始智能。"

这个判断的直觉非常清晰。当前的 AI 模型（哪怕是 GPT-4 级别）还没有聪明到能安全地改写自己的权重——这类似于让一个刚学会编程的实习生去重构整个操作系统内核。但让这些模型去优化工作流、改进工具调用策略、设计更好的评估机制？这完全在它们的能力范围内。

翁荔的论证有两层递进：第一层，Harness 先成为优化目标——用更少的启发式规则、更通用的机制，让系统本身成为可优化的对象；第二层，成熟的 Harness 反哺模型改进——一个能自主跑实验、评估结果、迭代策略的运行系统，可以支撑模型自身的研究循环。

Harness 自我改进的关键实验
DGM (Darwin Gödel Machine) — SWE-bench Verified 20% → 50%
DGM — Polyglot 多语言任务 14.2% → 30.7%
AHE — Terminal-Bench-2 优于人工设计 Harness
AHE 发现 — Harness 更新能力 9B 模型与 Claude Opus 过程同构
RE-Bench — 2 小时预算 AI 4× 人类得分
RE-Bench — 人类 8/32 小时 人类反超 AI

这些实验揭示了一个反直觉的模式：Harness 的改进收益是非单调的——中层模型（能正确调用工具、有长程指令跟随能力）从 Harness 改进中受益最大，而不是最强的模型。这说明 Harness 不是"越强的模型越不需要"——恰恰相反，它是一套可以被系统性地优化、迁移和复用的工程能力。

翁荔还指出了一个和 Prompt Engineering 的历史类比：当年大家疯狂研究 prompt 技巧，后来这些技巧被指令微调（instruction tuning）内化到模型行为中——但指定目标、约束、上下文和评估的需求从未消失，只是形式上移了。Harness 的改进很可能走同样的路：许多 Harness 层的优化最终会被内化为模型能力，但与外部上下文和工具的接口应当保留。

这篇博客几乎串起了过去一年 Harness Engineering 的全部主要研究方向——从上下文工程（ACE、MCE）到工作流搜索（ADAS、AFlow），从自我改进 Harness（STOP、Self-Harness）到进化搜索（AlphaEvolve、DGM）。翁荔的框架不是又造了一个新词，而是给散落在各处的研究提供了一个统一的坐标系。

🎯 对你意味着什么

  • 1 如果你是 AI 开发者，下一个竞争优势不在模型，而在 Harness 设计。 当基础模型能力趋于同质化（开源模型迅速逼近闭源），真正拉开差距的是那层"运行系统"：你的 Agent 如何分解任务、如何管理上下文生命周期、如何从失败中复盘、如何验证结果。Prompt Engineering 已经过时，Harness Engineering 正在成为新的技术壁垒。那些能把 Harness 设计得优雅、通用、可迭代的人，将拥有下一代 AI 产品的定义权。
  • 2 "人类被移出循环"的叙事是错的——人类应该上移到更高抽象层。 翁荔明确反对"AI 自主进化 = 人类不需要参与"的叙事。她的判断是：人类应该"往更高的抽象层移动"——从写代码到设计做实验的 AI，从调 prompt 到设计 Harness 的优化目标。这不是被淘汰，而是升级。人类在正确的时间、正确的抽象层次提供监督，这才是可持续的人机协作。
  • 3 评估（Eval）是 Harness 自我改进的瓶颈，也是最大的机会。 翁荔列出的七大挑战中，第一个就是"弱且模糊的评估器"——许多研究声明缺乏快速精确的验证器，研究品味、新颖性、长期科学价值难以量化。如果你现在投入一个 AI 相关项目，最可能产生复利的地方不是模型调优，而是设计一个可自动验证的评估体系。有可验证的奖励信号，强化学习才能跑起来；没有它，所有自我改进都是盲飞。

⚠️ 认知偏差提醒：模型中心主义（Model-Centrism）× 功能固着（Functional Fixedness）

我们有两个深层漏洞被这项研究精准利用。模型中心主义让我们本能地认为"AI 强不强 = 模型大不大"—— bigger is better 的 Scaling Law 叙事已经如此深入人心，以至于我们几乎忘了：GPT-4 的 API 调用和 Claude Code 的终端体验，差距不在模型本身，而在 Harness。一个 9B 模型配上精心设计的 Harness，可能在特定任务上击败裸跑的 GPT-4。

更隐蔽的是功能固着：我们习惯把 AI 当成"问答机器"或"文本生成器"，而不是"可以运行代码、读写文件、spawn 子进程、持续迭代的研究助手"。当 Harness 被优化为"可执行的搜索空间"时，AI 的能力边界就会指数级扩展——但前提是，你不再把它当成一个聊天框。
