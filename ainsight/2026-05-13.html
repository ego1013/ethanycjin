杰文斯陷阱：Token 降价 1000 倍，你的 AI 账单却涨了 320%——"便宜"是这个时代最贵的东西

1865 年，经济学家杰文斯发现蒸汽机越省煤，英国烧的煤反而越多。161 年后，同样的诅咒降临 AI：每百万 token 从 $60 降到 $0.06，企业 AI 总支出却从 115 亿暴涨到 370 亿美元。Token 越便宜，你用的越多；用的越多，总账单越失控。这不是 bug——这是经济学定律。

🔬 深度解读

先记住一组让人精神分裂的数字——

推理成本悖论：核心数据
GPT-3 价格（2021）→ 同等模型（2026） $60 → $0.06 / 百万 token
Token 单价降幅（3年） ↓ 1000 倍
企业 AI 总支出同期增长 ↑ 320%（$115亿 → $370亿）
推理占 AI 预算比例 33%（2023）→ 85%（2026）
仅 28% 财务领导者认为 AI 投资有清晰 ROI 72% 尚未看到回报

单价跌了 1000 倍，总支出涨了 320%。这两件事同时为真，而且不矛盾。这就是杰文斯悖论（Jevons Paradox）在 AI 时代的完美复现。

1865 年，英国经济学家 William Stanley Jevons 研究煤炭时发现了一个反直觉规律：瓦特的蒸汽机让煤炭燃烧效率大幅提升，理论上应该减少煤炭消耗——但英国的煤炭总消耗量不降反增，而且反弹幅度超过 100%。原因很简单：更高效的蒸汽机让之前"烧不起煤"的工厂、矿山、铁路、轮船统统用得起了。效率提升带来的不是节约，而是需求爆炸。

2026 年的 AI 推理经济正在精确重演这一幕。当每百万 token 36 美元时（GPT-4 时代），工程师精心优化每一次 LLM 调用，像对待黄金一样对待 prompt。当价格降到 0.15 美元时，工程讨论变成了"并行跑 3 个 Agent 还是 5 个？"——省下来的钱不是用来省的，而是用来花更多的。

到底是什么在吞噬你的预算？四个结构性的 token 倍增机制同时发力：

倍增机制 Token 放大倍数
──────────────────────────────────────────────
① 推理链 (Chain-of-Thought) 10-86×
2023年直接回答 ~7 token → 2026年推理模式 255-603 token
② Agent 循环 (Agentic Loops) 10-50×
每个任务触发 10-20 次 LLM 调用，Gartner 估算 5-30 倍
③ 上下文膨胀 (Context Bloat) 10-100×
RAG 注入企业文档 → 每查询 2万-10万 输入 token
④ 多 Agent 编排 3-10×
编排器+工作器+协调消息+综合调用
──────────────────────────────────────────────
复合效应：单价 ↓1000× × 每任务 token ↑50-100× = 总支出 ↑320%

Stanford 和 MIT 联合发表的最新研究（arXiv:2604.22750）用真实数据量化了这种爆炸。他们分析了 8 个前沿模型在 SWE-bench 编码任务上的 token 消耗，发现了三个让人倒吸凉气的事实——

Stanford/MIT 研究：AI Agent Token 消费真相
Agent 编码任务 vs 普通对话 token 消耗 1000 倍
同任务多次运行的 token 差异 高达 30 倍
模型自我成本预测的最高相关系数 仅 0.39（且系统性低估）
花更多 token 是否更准确？ 否。中等成本时准确率最高

最后一条数据尤其致命。这意味着 token 消耗存在一个甜蜜点（sweet spot）：花太少不行，花太多也不行——但 AI 自己不知道这个甜蜜点在哪（自预测相关系数仅 0.39），而且它总是倾向于低估自己会花多少。你把预算交给一个不知道自己会花多少钱、而且习惯性报低价的 Agent？

真实世界的案例更加生动。一位开发者使用 Claude Code 编程 8 个月，消耗了 100 亿个 token——按标准价格超过 15,000 美元。有组织报告月度 AI 账单达到数千万美元。更诡异的是，AI 生成代码后还需要 AI 审查代码——每次审查成本 15-25 美元。机器在给自己打工，而你在为双份工作买单。

OpenRouter 的 2025 年报告（超过 100 万亿 token 真实流量数据）证实了趋势：13 个月内，每次请求的平均输入 token 增长了 4 倍，输出 token 增长了 3 倍，推理模型占总消耗比例超过 50%。

连起来看：#012 告诉你 AI 加速个人但组织更慢了（速度悖论），#018 告诉你 Agent 步骤越多越不靠谱（可靠性崩塌），今天 #019 告诉你每多一个 Agent 步骤不仅更不靠谱，而且更烧钱——而且是以你完全无法预测的方式烧。三者叠加的画面是：企业正在用越来越多的钱，买越来越快但越来越不可靠的 AI 自动化——而且不知道自己在花多少钱。

Sam Altman 曾经说 AI 智能将变得"便宜到无法计量"（too cheap to meter）。他可能是对的——但不是他想的那个意思。"无法计量"描述的不是价格低，而是你真的无法计量自己会花多少。

🎯 对你意味着什么

  • 1 把你的 AI 成本指标从"每 token 多少钱"换成"每个有用结果多少钱"。Token 单价是供应商给你看的虚荣指标。你真正需要追踪的是：生成一份合格的代码审查报告花了多少钱？处理一个客户工单的端到端推理成本是多少？一个 Agent 完成一个 SWE-bench 级别的编码任务可能消耗 100 万+ token——这才是你的真实成本单元。每周做一次 AI 账单审计，按"结果"而非"调用次数"归类支出。
  • 2 为每个 Agent 工作流设置硬性 token 预算上限（Budget Cap）。Stanford/MIT 研究发现同一任务多次运行 token 差异高达 30 倍，且花更多 token 不等于更准确。这意味着没有 cap 的 Agent 就像没有信用额度限制的信用卡。在编排层设置 max_tokens 硬上限，超出即终止并回退——宁可失败也不要无限制烧钱。Stanford 数据显示中等成本时准确率最高，所以 cap 本身还能提升质量。
  • 3 实施分层路由（Tiered Routing）：80% 的请求不需要前沿模型。像数据分类、格式转换、简单问答这类任务，用小模型或缓存命中就够了，把前沿模型留给真正需要复杂推理的 20%。语义缓存（Semantic Cache）可以节省 30-50% 的 API 调用。组合策略：小模型 + 语义缓存 + 前沿模型路由，可以在不损失质量的前提下把总成本压缩到 1/3。

⚠️ 认知偏差提醒

单位成本偏误（Unit Cost Bias）——当你看到"每 token 成本下降了 10 倍"时，大脑会自动把它翻译成"我的 AI 支出将减少 10 倍"。但你消费的不是 token，而是结果，而每个结果消耗的 token 数量可能在同一时期增长了 100 倍。这和你去 Costco 买大包装零食的心理完全一样——单价便宜了所以买了更多，结果花得更多。杰文斯悖论不是异常，它是效率提升的默认结局。唯一的反制是预先设定总额度，而非盯着单价自我安慰。
